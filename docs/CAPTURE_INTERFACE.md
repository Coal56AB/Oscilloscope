# Интерфейс захвата, Linux ABI 4

## Raw samples и метаданные

Формат 2: базовые отсчёты — unsigned 8-bit offset binary, два канала, в памяти `CH1[t], CH2[t], CH1[t+1], CH2[t+1]`. Для двух ветвей A/B такт входа packer содержит CH1_A, CH2_A, CH1_B, CH2_B; B следует за A во времени. Порядок проверен RTL-стендом; достоверность кодов и калибровка интерливинга на плате пока не измерены.

`CaptureBuffer` хранит pointer/capacity/bytes, sequence, sample_rate_hz **на канал**, first_sample, trigger_sample (абсолютные индексы), аппаратное и software время, flags, volts_per_code и zero_code на канал. Нет триггера: UINT64_MAX. `volts=(code-zero_code)×volts_per_code`. Calibration аппаратного source задаёт вызывающая сторона; численные значения demo не относятся к плате.

`DisplayFrame` содержит Y, min/max, FFT, карту плотности и измерения только для отображения. Для включённого канала карта используется и обычным следом, и coloring; выключенный канал пропускает проекцию. Три слота разделяют обработку, готовый кадр и копирование потребителем; mutex защищает только смену владельца слота. Raw запись имеет независимую глубину; при остановке она сохраняется под владением processor. Изменение view повторно обрабатывает исходные данные, не старые Y.

MIN/MAX, mean/rms и временные Measurements относятся к обработанному каналу
до экранного сжатия. `raw_mean`/`raw_rms` относятся к равномерным исходным
отсчётам до FILTER, подавления шума и коррекции АЧХ; их используют ZERO/NOISE
и оценка шума при калибровке АЧХ. Эти поля не меняют формат OSCRAW1 или CSV.

## Регистры PL и аппаратный блок

В текущем bitstream AXI DMA S2MM/SG находится по `0x40400000`, IRQ F2P[1]
(GIC SPI 30), capture AXI GPIO — по `0x41210000`. OLED сохраняет `0x41200000`.
GPIO.DATA offset 0, bit 0 включает поток; GPIO.DATA2 offset 8 содержит
`0xADC50000 | overflow`. DATA[5:1] выбирает частоту по `capture_rates.h`,
DATA[10:6] задаёт payload shift, DATA[13:11] — диагностический делитель
физического encode `2^shift`. Ненулевой clock shift отключает прореживание
и сохраняет обе ветви A/B. Настройки меняются при выключенном потоке.
DATA[31:14] — необязательная конфигурация предварительной проверки триггера:
внутри этих 18 бит уровень в кодах АЦП занимает bits 0…7, код мощности шума
8…15, канал 16, enable 17. Старый bitstream игнорирует эти линии.
Такты АЦП от enable не зависят. Проверка ID обязательна
до запуска DMA. Register version=5, bitstream interface version=1;
идентичность конкретной сборки отдельно публикуется штатным SHA-256 bitstream.

Один AXIS пакет содержит 64 байта заголовка и `8 << payload_shift` байт
отсчётов (shift 0…17), TLAST на последнем 64-битном beat.
Первые 64 байта — little-endian заголовок:

| Offset | Содержимое |
|---:|---|
| 0 | uint32 magic `0x5043534F` (OSCP) |
| 4 | uint32 header version 4 |
| 8 | uint32 payload bytes |
| 12 | uint32 effective sample rate per channel |
| 16 | uint64 sequence |
| 24 | uint64 first_sample |
| 32 | uint32 flags: bit 1 — Peak Detect |
| 36 | uint32 ноль в MMX1; raw min/max в MMX2 |
| 40 | uint64 sequence предыдущего payload, если есть сводка |
| 48 | uint8 CH1 min, CH2 min, CH1 max, CH2 max предыдущего payload |
| 52 | uint32 magic сводки `0x31584D4D` (MMX1) |
| 56 | uint32 bytes предыдущего payload |
| 60 | uint32 sample rate предыдущего payload |

Сводка — необязательное расширение заголовка версии 4. Первый блок после
сброса содержит нули в offset 40…63. Минимумы и максимумы вычисляются в PL
на равномерных representative-парах; нативная Peak Detect огибающая в них
не входит. Адаптер принимает сводку только при правильном magic, смежных
sequence, совпадающих длине и частоте. Со старым bitstream используется
обычный программный поиск.

MMX2 (`0x32584D4D` в offset 56) заменяет резерв offset 36…63 статистикой
скользящего окна из 17 равномерных отсчётов. Offset 36 содержит raw min/max
CH1/CH2; offset 40 и 48 — uint64 для CH1 и CH2: min суммы (bits 0…12),
max суммы (13…25), max величины `17*sum(code²)-sum(code)²` (26…48),
остальные биты нулевые. Offset 60 содержит младшие 32 бита sequence
описываемого блока. Полный номер равен номеру текущего заголовка минус 2.
Среднее получается делением суммы на 17, дисперсия — делением на 289.
Окна центрированы; восемь следующих отсчётов приходят в следующем payload,
поэтому сводка передаётся с задержкой двух блоков. Первый блок не имеет
полного левого контекста и не получает MMX2. При payload меньше 4096 байт
сохраняется MMX1. MMX2 содержит только статистику исходных кодов.

MMX3 (`0x33584D4D` в offset 56) сохраняет нижние 49 бит статистики MMX2.
В старших 15 битах слова CH1 находятся bits 0…14 конфигурации проверки,
в старших битах слова CH2 — оставшиеся 3 бита конфигурации, затем LOW и HIGH;
остальные 10 бит нулевые. Поля sequence и raw min/max прежние. Программная
часть использует LOW/HIGH только при совпадении всей конфигурации с запросом.
При выключенной проверке передаётся MMX2; отсутствие расширения не мешает
обычному поиску.

Проверка определяет возможность достижения каждой стороны уровня для
каждого отсчёта по его исходному значению, сумме и дисперсии окна из 17 точек.
Деления нет: сравниваются произведения с одинаковыми знаменателями. Код
мощности задаёт интервал, содержащий точную программную оценку: при `e=code>>5`
и `m=code&31` нижняя граница равна `m` для e=0, иначе `(32+m)<<(e-1)`;
верхняя — соответственно `m+1` или `(33+m)<<(e-1)`. Обе границы проверяются
вместе с ветвью сохранения коротких импульсов при большой дисперсии.
Уровни проверки на один код ниже и выше целочисленного уровня расширяют
множество кандидатов. Округление может добавить работу CPU, но не удалить
разрешённый обработкой фронт. Код 0 проверяет исходные значения, 255 — точное
среднее 17 точек для FILTER MEDIUM без NOISE. При непредставимой мощности
остаётся MMX2. Последующие выпуклые фильтры не расширяют диапазон этих точек.

Предварительный отбор оставляет DMA-блок под владением до получения его
сводки в одном из двух следующих заголовков. Для пропущенного тихого блока сохраняется
контекст; перед возможным фронтом его хвост добавляется в историю вместе
с полным текущим блоком. Следующий блок также проходит обычный поиск,
чтобы сохранить posttrigger и запас фильтра у границы. Отбор применяется
только если глубина записи помещается в один входной блок; ROLL, DEBUG,
калибровка и FORCE используют полный путь. Проверка границ — необходимое
условие пересечения гистерезиса; точный фронт и его время определяет общий
программный детектор. Полная запись выбранной глубины сохраняется.

Для показа первого принятого захвата потребитель включает подтверждение
`capture_pipeline_presented` и передаёт capture_id после фактического вывода.
До подтверждения следующая запись не заменяет ожидающий кадр. Одновременно
допускается подготовка двух записей на разных стадиях обработки и показа;
потребителю она выдаётся после показа предыдущей. При занятости обеих стадий
DMA продолжает работать, свежий контекст сохраняется; после освобождения
стадии поиск начинается на новых входных данных. Блоки этого времени и
полного holdoff учитываются отдельно от потерянных и исключённых по
аппаратным границам.

Payload выбирается по частоте и глубине записи: минимальная степень двух,
вмещающая запись, при прежнем потолке 1 МиБ и 40 мс. Для 100K это
131 072 эффективных отсчёта: 256 КиБ без Peak Detect или 512 КиБ с ним.
Если запись длиннее предельного блока, её собирает история. Во время
deadtime такая история продолжает заполняться, чтобы сохранить полную
предысторию после освобождения стадии вывода.

При действующей калибровке NOISE программная часть выводит из MMX2
консервативные границы результата того же адаптивного подавления шума.
Минимум/максимум средних и верхняя граница дисперсии ограничивают вес
исходного отсчёта в Wiener-оценке. При большой дисперсии сохраняется полный
диапазон исходных кодов и средних; короткий разрешённый импульс не
отбрасывается по среднему. Дальнейший FILTER является выпуклым средним
и не расширяет диапазон обработанных входов. Значения округляются наружу.

Без Peak Detect идут пары `CH1[t],CH2[t],CH1[t+1],CH2[t+1],…`.
При CONFIGURE с rate_index > 0 каждый 8-байтный beat содержит две равномерно
выбранные пары (4 байта), затем CH1 min, CH2 min, CH1 max, CH2 max (4 байта).
Экстремумы охватывают все A/B-преобразования интервала этих двух пар, включая
отброшенные при прореживании. Длина во времени — два эффективных отсчёта.
`first_sample` увеличивается на payload/4 вместо payload/2. TEST_CLOCK
сохраняет обычные A/B-пары без Peak Detect при любом физическом делителе.
Адаптер распаковывает representative-пары и отдельный `CaptureBuffer.peaks`
одинакового размера в кешируемую память; флаг — `OSC_CAPTURE_PEAKS`.
Кольцо истории и снимки копируют обе части согласованно. FFT, триггер,
среднее и RMS используют равномерные отсчёты; огибающая и min/max — экстремумы.
Peak Detect сохраняет огибающую, но не восстанавливает частоту выше Nyquist.
На 200 MSa/s используются A и B; на меньших частотах выбирается ветвь A
с равномерным целым периодом. Счётчики относятся к эффективным отсчётам,
сбрасываются при новом open и CONFIGURE;
входные преобразования и конвейер прогреваются до его включения.
`hardware_ns=first_sample*1e9/sample_rate_hz` — относительное время отсчётов,
не wall clock и не время IRQ. Несовпадение заголовка завершённого DMA-блока
возвращает ошибку. Подключение и расчёт задержек — [ADC_CAPTURE.md](ADC_CAPTURE.md).

## Linux UAPI

`capture_uapi.h` задаёт fixed-width structs с __aligned_u64, одинаковыми для ARMv7 и 64-bit userspace. GET_INFO возвращает ABI/register/sample/bitstream versions и геометрию DMA ring. mmap — только выделенная драйвером память, read-only для приложения. DEQUEUE после poll возвращает completed buffer index/bytes/data_offset/sequence/timestamps/trigger; RELEASE явно возвращает владение. Неверные размеры/индексы/версии отвергаются адаптером.

Software ceiling — 128 блоков. Реальный драйвер выделяет 16 блоков по 2 МиБ; GET_INFO.block_bytes — шаг между блоками, включая аппаратный заголовок. DEQUEUE.data_offset=64, bytes содержит только payload. Адаптер проверяет сумму offset+bytes, выравнивание, версии и флаги до доступа к отображению.

CONFIGURE принимает rate_index 0…19 и payload_shift 0…17. При существующем
lease возвращает EBUSY. Драйвер завершает текущий поток, сбрасывает очередь
и запускает новый с соответствующими длиной дескрипторов и GPIO-настройкой.
Приложение выбирает длительность блока не более 40 мс, максимум 1 МиБ payload.

SET_PROBE (`_IOW('O',0x15,struct osc_capture_probe)`) принимает 18-битное
control без активных leases. Он сохраняет конфигурацию для следующего
CONFIGURE; TEST_CLOCK отключает проверку. Старое ядро возвращает ENOTTY:
адаптер запоминает отсутствие поддержки и использует MMX1/MMX2 либо полный
поиск. ABI 4 и register version 5 сохраняются, payload и его исходные коды
не меняются.

TEST_CLOCK принимает clock shift 0…6 и payload shift 0…17; ограничения
владения буферами те же, что у CONFIGURE. Физическая частота ветви равна
`100000000 >> shift`, частота в заголовке — `200000000 >> shift`.
При старте FPGA и новом open выбран shift=6. CONFIGURE возвращает shift=0
и штатное прореживание. Закрытие останавливает поток, сохраняя последнюю
физическую частоту. Порядок проверки — [STARTUP_CHECKS.md](STARTUP_CHECKS.md).

Между DEQUEUE и RELEASE DMA не пишет в leased buffer. coherent allocation
обеспечивает согласование CPU/device; перед разбором завершения используется
dma_rmb. RELEASE возвращает блок в SG-очередь. При закрытии устройства DMA
останавливается; память удерживается до освобождения mmap references.
Приложение не получает физический адрес, mmap read-only, повышение до записи
через mprotect запрещено. Входное overflow и отсутствие завершений дают POLLERR;
пропуск аппаратного sequence даёт OSC_CAPTURE_DISCONTINUITY.

`ZYNQ7020/linux/driver/oscill_capture.c` встроен в ядро через Buildroot hook.
`capture_zynq.h/c` обслуживает mmap/poll/ioctl и leases. `capture_pipeline`
подключает его отдельным worker. `capture_history` копирует полный принятый блок
в кешируемую линейную историю, затем worker возвращает DMA lease. Разрыв first_sample или
смена частоты очищает накопленную историю. Поиск читает заимствованное представление истории. Принятый участок
выбранной глубины копируется в общее кольцо из трёх записей; отдельный
processing worker удерживает запись для STOP и повторной обработки. Программная подмена
выполняется только после DEQUEUE; сведения о времени/sequence не генерируются.
Отсутствие устройства возвращает ошибку без перехода на демоданные.

## Файл OSCRAW1

`capture_file.h/c` — версия 1, header 128 байт, затем полный raw payload. Все целые little-endian, calibration IEEE-754 binary64. В заголовке: magic `OSCRAW1\0`; ABI/header length/channels/format; rate/first/sequence/trigger/hardware/software timestamps; payload length; два gain, два zero; flags. Смещения соответствуют serializer в исходниках. CRC32 IEEE отдельно для metadata bytes 0…115 и raw payload; поле metadata CRC offset 116, payload CRC 120, reserved 124.

Reader проверяет длину, версии, диапазоны, finite calibration, CRC и отсутствие лишних байтов. Большие captures не сериализуются через CSV или экранные координаты. Прежний BMP/CSV codec сохранён; он остаётся форматом совместимого экранного экспорта. Бинарный writer имеет FILE API, а не скрытые пути или временные файлы. UI фонового сохранения полного raw capture пока не подключён.
