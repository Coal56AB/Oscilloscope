## Реализованная часть

GUI перенесён с локальным резервом истории. Работают переносимые raw источники/кольцо/processor/бинарный codec, threaded demo pipeline, UART codec/queue/reconnect и переносимая STM32 обработка кнопок/энкодеров. SDL frontend подключает raw и serial, framebuffer/DRM и evdev с поиском мультитач-устройства. RTL packer имеет выполненную simulation. Собраны PS/DDR/VDMA/VTC/TMDS проект, FSBL и диагностический `BOOT.BIN` для TF1. Полный Buildroot комплект с U-Boot, Linux, rootfs и GUI собран в SD/QSPI образы; оба варианта загрузки и отрисовка GUI проверены в ARM эмуляторе.

## Следующий порядок работ

1. Проверить полный part/speed suffix и реальный PS DDR handoff. Подтвердить питание USB Host/VBUS, модель дисплея и допустимые video timings; схему UART STM32 и свободные PL pins. Установленные GPIO/clock нельзя угадывать.
2. Запустить собранный тест DDR/HDMI с TF1; затем Linux с GUI и touch на том же аппаратном проекте. Проверить совместимость фиксированного режима 1024×600 при pixel clock 50 МГц. Для page flip реализовать DRM driver для фактического VDMA/VTC; первый запуск использует framebuffer, настроенный FSBL.
3. Подключить ADC I/O/CDC/phase ordering, FIFO overflow/drop counters, timestamps и PL trigger/pretrigger. Packer допускает backpressure, реальный АЦП остановить им нельзя: overflow должен быть обработан явно.
4. Реализовать DMAEngine SG kernel driver по согласованному `capture_uapi.h`; проверить mmap/cache/vладение и подключить lease source к pipeline. Пока `capture_zynq.c` не используется как source общего pipeline.
5. Довести raw GUI: фактический trigger/pretrigger, полный обзор записи/курсорные значения, persistence/smoothing и связь настроек acquisition. Сейчас эти функции исходного демо остаются самостоятельными; raw экспериментальный режим не является их аппаратной реализацией. При ограничении view глубиной записи нужно согласовать фактическую подпись развёртки и CSV metadata.
6. Добавить bounded storage worker, raw export/browser и безопасную обработку извлечения/заполнения карты. Существующие BMP/CSV операции пока синхронны. Большие записи не должны блокировать GUI или переиспользовать DMA-owned буферы.
7. Проверить сгенерированную прошивку STM32 на модуле: GPIO, направление и детенты энкодеров, debounce и UART. BSP и неблокирующий транспорт реализованы; проверить физический обмен через USB–UART мост панели и hub к USB Host Zynq. Прошивку через ST-Link владелец подтвердил.
8. Проверить на плате загрузку/восстановление QSPI и выполнить аппаратные нагрузочные проверки. Готовый образ имеет один системный слот; A/B обновление не реализовано. Требуемые 400 МБ/с с HDMI и запасом пока не измерены.
9. Снять временные отметки FPGA DONE → `SPLASH_READY` → U-Boot → ядро → init → GUI по UART и сравнить с появлением изображения на HDMI. После удаления программных пауз владелец подтвердил появление заставки при остановленной загрузке в U-Boot примерно через 4 секунды; Linux для раннего вывода не требуется. Переподключение HDMI работающего GUI без reset платы даёт примерно 2,5 секунды до изображения. Это приблизительные наблюдения; задержка дисплея подтверждена этим опытом, момент начала корректного HDMI-сигнала не измерен. Перенос заставки в отдельную PL-логику не выбран без измерения оставшейся задержки. Подробности — [TESTING.md](TESTING.md).

Подробные расчёты — [PERFORMANCE.md](PERFORMANCE.md), выполненные проверки — [TESTING.md](TESTING.md), сборка и прошивка — [BUILD.md](BUILD.md), [FLASHING.md](FLASHING.md). Недостающие аппаратные части нельзя заменить фиктивным драйвером или утверждением об успешном запуске.

## 21.10.2026 — масштабы каналов принадлежат STM32

- STM32 хранит масштабы CH1/CH2, применяет шаги энкодеров и выбирает реле по схеме входного делителя. GUI получает итоговые мВ/дел после паузы установления; шаг масштаба повторно на GUI не применяется. Изменение с сенсора/меню — абсолютный запрос к панели. Коэффициент щупа и просмотр сохранённых осциллограмм остаются в GUI.
- Шесть реле PA0…PA5 и ADC питания PB1 подтверждены по `Interfaces.SchDoc`; резисторы делителей и драйверы — по `AnalExtend.SchDoc`/`DiffMeasure.SchDoc`. Таблица реле рассчитана по номиналам для восьми делений и номинального диапазона AD9288 1,024 Vpp. Калибровка и время установления не выдаются за измеренные характеристики.
- Один общий кодек обслуживает оба направления UART. STM32 принимает RUN и назначение энкодеров, выдаёт масштабы и питание. Разбор команд находится в главном цикле; аппаратный приём не блокирует энкодеры. Напряжение не преобразуется в процент заряда без данных об источнике питания.
- `STM32_STANDALONE_DEBUG=1` включает автономный выбор масштаба и местное переключение LED кнопкой RUN при отсутствии команд GUI две секунды. При связи с GUI действуют штатные команды RUN и режима позиции; повторные команды GUI поддерживают связь. Значение 0 оставляет RUN под управлением GUI. Настройки и проверка — [STM32.md](STM32.md), [TESTING.md](TESTING.md).
- Подтверждённый владельцем путь панели — USB–UART мост STM32 через общий с сенсором hub в PS USB Host Zynq. В Linux включены CH341/CP210x/CDC ACM; GUI по умолчанию ищет панель на USB serial устройствах и повторяет поиск после отключения. До первого валидного пакета панели команды в порт не отправляются. Консоль UART Zynq остаётся отдельной.
- Из главного цикла STM32 убран `WFI`: владелец подтвердил обычное подключение и прошивку через ST-Link без дополнительных действий.

## 22.10.2026 — задний служебный OLED

- По указанию владельца K1 переключает отдельные страницы GUI/HDMI, захвата и обработки, связи, питания/аккумулятора, хранилища, системы/версий, ошибок и температур. GUI-кадры и обработка сигнала имеют разные метрики. Все доступные температурные каналы показываются с именами; дополнительные страницы входят в цикл кнопки.
- Отдельная служба получает неблокирующие datagram-снимки из главного цикла GUI и обнаруживает зависание по heartbeat. Отсутствие службы не блокирует GUI. Новая ошибка один раз открывает страницу ошибок, после этого K1 остаётся доступной.
- AXI GPIO OLED и PL-кнопок добавлен по подтверждённым выводам схемы. Уточнение 23.10: это K3/K2; физическая K1 идёт в PS MIO0 и обслуживается отдельно. UIO предоставляет только отдельный регистровый блок, без `/dev/mem`. Транспорт/шрифт/профиль SSD1306 перенесены из study и используются Linux и FSBL без зависимости от соседнего репозитория. Маркировка контроллера OLED не подтверждена схемой.
- Напряжение берётся из телеметрии STM32. По последующему уточнению владельца возраст остаётся внутренним, отсутствующие/устаревшие показания отображаются прочерком. Температур несуществующих датчиков и раздельных температур PS/PL из одного измерения нет. Подробности и границы — [STATUS_DISPLAY.md](STATUS_DISPLAY.md).

## 23.10.2026 — масштаб энкодеров, отладка нажатий и STOP

- Положительный шаг CH1/CH2 в режиме SCALE уменьшает В/дел, увеличивая изображение сигнала. Направление изменено и в GUI, и у владельца аппаратного масштаба STM32; режим POSITION и сенсорные кнопки масштаба сохраняют прежние направления.
- DEBUG содержит GENERATOR, LONG PRESS (200–1500 мс) и DOUBLE CLICK (100–1500 мс), шаг настройки 50 мс. Значения по умолчанию — по 300 мс. Windows/Linux используют одну настройку удержания из модели GUI, включая кнопки, клавиатуру и касания; Linux также использует её для DOWN/UP панели. Изменения действуют до перезапуска. Выбор шрифта временно скрыт; INTER и радиусы 5/10 px сохранены.
- STOP хранит исходную запись демосигнала: настройки триггера меняют маркер и параметры следующего захвата, а масштаб/позиция меняют представление существующих отсчётов. Повторная генерация разрешена при RUN и явном FORCE, включая одиночный захват. Это проверка программного симулятора, а не аппаратного захвата АЦП.

## 23.10.2026 — устранение люфта фаз и выход из меню удержанием

- Ошибка декодера воспроизведена без платы: после недопустимого перехода остаток счётчика смещал выдачу относительно детентов и поглощал первый обратный щелчок. Общая библиотека завершает 4/2-переходные детенты только на опорных фазах и очищает повреждённый остаток при возвращении в них. Уточнение после проверки владельцем: рабочую опору задаёт конфигурация, начальный снимок GPIO её не заменяет. Временные таймауты и инверсия направлений не добавлены. Общий алгоритм остаётся в PeriphGeneral, GPIO-карта и владение масштабами не меняются.
- Удержание отдельной кнопки CH1, CH2, CURSOR или TRG MODE закрывает её открытое меню; MENU/BACK закрывает любое меню. Незавершённое редактирование отменяется. Для закрытого меню сохраняется открытие настроек кнопками, MENU удержанием включает ZOOM. Кнопки энкодеров сохраняют свои функции. После удержания CH1/CH2 короткого действия нет, последовательность двойного клика очищается.
- По указанию владельца DOUBLE CLICK по умолчанию 300 мс. Он используется только для выключения CH1/CH2; LONG PRESS также остаётся 300 мс и настраивается независимо.

## 23.10.2026 — независимая от старта опора энкодера и исправление K1

- После проверки владельцем запуска между фиксациями убрана зависимость опорной фазы от первого снимка GPIO. Encoder_Init принимает detent_state явно, целевой параметр STM32_ENCODER_DETENT_PHASE=3 (11) задаёт программную границу; частичный путь до первой границы не выдаёт шаг. Это выбранная настройка, не измеренная фаза всех установленных EC11E. Смена направления, SCALE/POSITION и опрос GPIO не инвертируются повторно.
- K1 на схеме — PS MIO0/E6; M19 относится к PL KEY2 и физической K3. Перелистывание OLED перенесено в отдельный транспорт PS GPIO через character-device API, с запросом только одной входной линии. Назначение исправлено в документации; нет подмены вывода FPGA и доступа к произвольной физической памяти. Существующие bitstream и FSBL подходят.
- На этом этапе подтверждена доступность внутреннего датчика STM32F103 через ADC_IN16. Реализация телеметрии добавлена следующим изменением ниже. Для OLED и HDMI-экрана доступный канал температурной телеметрии не подтверждён; показания не моделируются.

## 23.10.2026 — температура STM32 и понятные показания OLED

- По требованию владельца реализован весь путь температуры STM32: неблокирующие ADC16/17, расчёт по типовым параметрам ST и отношению к VREFINT, общий UART-пакет TEMPERATURE=10, snapshot serial transport, локальный status IPC и строка STM32 на OLED. ADC9 питания сохранён в том же последовательном цикле. Отдельного потока и ожидания ADC в опросе энкодеров нет.
- Температура относится к кристаллу; V25/slope/VREFINT — типовые коэффициенты, не индивидуальная калибровка. Ошибочные отсчёты отвергаются, ошибка передаётся INT32_MIN. Точность на установленном чипе не измерена; канал температуры экрана не выдумывается.
- Общее правило для OLED: простые подписи, актуальное значение или прочерк. Возраст, FRESH/STALE/UNAVAILABLE/N/A и пояснения о неподключённых аппаратных функциях убраны с обычных страниц. Ошибки/пропуски UART перенесены на Errors; подробная статистика захвата остаётся в --diagnostics. Проверка актуальности действует внутри, предыдущее значение после отказа не остаётся на экране.
- Для STM32 всегда зарезервирована строка, даже со старой прошивкой/без панели. XADC подписан ZYNQ. Для получения температуры нужны новые прошивки обеих сторон; формат осциллограмм BMP/CSV не меняется.

## 23.10.2026 — масштаб времени сохранённой записи в STOP

- Уточнение владельца: в STOP время/дел продолжает менять ширину сигнала. При уменьшении изображения за пределами записанного времени остаётся пустая сетка, данные там не восстанавливаются и не генерируются заново. Общий waveform_view сохраняет запрошенный шаг времени, вместо обрезания всего интервала с последующим растяжением на экран.
- Отсутствующий экранный отсчёт обозначен WAVEFORM_NO_SAMPLE (INT16_MIN); остальные значения ограничены INT16_MIN+1…INT16_MAX. Линии, min/max, послесвечение, фильтрация и FFT учитывают пропуски. Измерения используют доступные точки, при отсутствии точек показывают прочерк. После изменения вида в STOP старая история не подменяет текущий масштаб.
- Правило действует для генератора, просмотра CSV и raw pipeline. В raw отделён запрошенный экранный интервал от пересечения с памятью: обработка и статистика читают только реальные отсчёты, acquisition в STOP не запускается. ZOOM после изменения основной развёртки использует её физический шаг. Исходная запись, sequence и привязка к триггеру сохраняются.
- Схемы файлов BMP/CSV не менялись: CSV по-прежнему содержит int16 координаты; INT16_MIN сохраняет пропуск при повторном открытии. Старые файлы без пропусков читаются прежним способом. Изменение относится к Zynq/настольному GUI, STM32 не меняется.

## 23.10.2026 — реальный приём AD9288 с подменой после DMA

- По требованию владельца DEBUG сохраняет физический захват: обе AD9288 тактируются и читаются FPGA, данные проходят FIFO/CDC/AXI DMA/HP0 в DDR. Симулируемые значения создаются только после получения завершённого блока; sequence, first_sample, время и пропуски остаются аппаратными. При ошибке перехода на чистый программный генератор нет.
- Соединения взяты из текущей основной схемы и листов 5/9 MINI rev B. Учтена разная нумерация XS1/CAM1. CLK_A/CLK_B — две общие линии, UART панели использует USB. Для S1=1/S2=0 ветви принимаются в разных полупериодах. 100 МГц на ветвь и 200 MSPS на канал — выбранные частоты; работа установленной платы и запас входных таймингов не объявляются измеренными.
- Linux владеет coherent DMA-памятью и SG, GUI получает read-only leases. Неполученные READY-блоки можно переиспользовать, leased-блоки нельзя. STOP удерживает запись, включая режим подмены; FORCE требует нового блока. Для первичного запуска применяется программный триггер внутри блока; аппаратный кольцевой pretrigger остаётся отдельной работой.
- Общая математика генератора вынесена из UI в signal_generator. Формы и частота DEBUG применяются к следующему захвату, Windows/Linux сохраняют настольный симулятор. Регистры, размеры, номинальная шкала и порядок проверки платы описаны в [ADC_CAPTURE.md](ADC_CAPTURE.md); ABI 2 — в [CAPTURE_INTERFACE.md](CAPTURE_INTERFACE.md). BMP/CSV и файловый OSCRAW1 не меняются.
- Упаковка 32→64 бит выполняется перед FIFO. Заголовки вставляются после FIFO: выход имеет запас полосы для разгрузки накопленных отсчётов. Приём IOB захватывает слово предыдущего периода encode; setup и hold проверяются отдельно, без переноса hold на лишний период.
- После наблюдения стартового overflow на плате reset последующих AXIS IP отделён от разрешения отсчётов: между ними выдерживаются 32 такта. Стенд приёмника использует реальный преобразователь ширины Xilinx и проверяет его задержку READY после reset. Первую причину отказа Linux-драйвер сообщает в dmesg.

## 23.10.2026 — скорость консоли P1

- По запросу владельца скорость по умолчанию — 1000000 бод, 8N1: FSBL, U-Boot, Linux console и SD boot script согласованы. Getty сохраняет установленную скорость. При 8N1 расчётный предел полезных байтов UART — 100000 байт/с до накладных расходов передачи; это не измеренная скорость загрузки прошивки. Vivado 2019.1 принимает PCW_UART1_BAUD_RATE=1000000, но генерирует делители 115200, а XUartPs_SetBaudRate ограничен 921600. FSBL явно задаёт делители 20 и 4 при UART clock 100 МГц после ps7_init, до печати баннера; соответствие частоты и порта проверяется при компиляции.
- Существующий выбор PC → UART BAUD расширен до 2000000. Изменение применяется к ttyPS0 на время работы; после перезагрузки возвращается скорость по умолчанию. Панель STM32 использует отдельный USB-порт и прежние 115200 бод.
- P1 подключён через CH340E: смена скорости COM-порта на ПК не сообщает новое значение Zynq. Скорости терминала и прибора выбираются согласованно; автоподстройка и протокол обновления Linux через UART этим изменением не добавлены.

## 23.10.2026 — завершение DMA и пустой экран до первого блока

- На плате DMA записал заголовок и данные в первый 2-МиБ буфер, но статусы дескрипторов оставались нулевыми. В сгенерированном IP обнаружен C_SG_INCLUDE_STSCNTRL_STRM=1 с TVALID дополнительного status stream, привязанным к нулю. По PG021, стр. 55, при этом EOF-дескриптор не обновляется до получения статуса. Для захвата этот необслуживаемый интерфейс явно отключён; сборка проверяет параметр.
- Интеграционный RTL-стенд использует настоящие IP упаковки, FIFO и CDC, проверяет заголовки, данные, TLAST, переполнение и повторное включение. До первого внешнего кадра GUI очищает и отсчёты, и min/max, FFT и сохранённые массивы: остаточный демографик не выдаётся за запись АЦП.

## 23.10.2026 — обновление через Oscill Terminal

- По запросу владельца обновление выполняется из вкладки «Прошивка» существующей терминалки. Перед записью дважды читается QSPI, копия сохраняется на ПК и сверяется с SHA-256 всей flash. Затем передаются BOOT.BIN и image.bin фактической длины; заполнение полного qspi.bin, резерв и настройки не передаются и не перезаписываются. Нули внутри самих файлов не обрезаются.
- Linux останавливает GUI/захват и показывает отдельный экран обновления. Драйвер записи MTD отделён от отображения; оба файла и назначения проверяются до первого erase, каждый записанный блок читается обратно. Передача проверяется SHA-256, запись дополнительно проверяет CRC файлов. Поддержка записи включена только для разделов boot и linux-fit, резерв окружения остаётся read-only.
- Для первой установки поверх старой read-only прошивки терминалка загружает новый FIT в RAM через существующий U-Boot loadb, проверяет CRC32 и запускает Linux без предварительной записи flash. Для последующих обновлений этот этап не нужен. Прошивка остаётся односекционной; A/B и автоматическое восстановление при пропадании питания не добавлены.
- RAM-загрузка передаёт `oscill.update=1`: init показывает экран обновления без запуска захвата с прежним FPGA. В xilinx_dma исправлено ожидание регистра: Linux 6.6 при нулевой задержке расходовал номинальный секундный бюджет за миллиард итераций. Задержка 1 мкс ограничивает число чтений и устраняет многоминутную остановку после ошибки DMA, наблюдавшуюся на плате.
- После отключения status stream на плате появился первый IRQ DMA, но на границе партий возникал overflow. Вместо ожидания завершения всей партии драйвер AXI DMA выдаёт IRQ каждого блока и дополняет активную SG-цепочку. LEASED-буферы остаются исключёнными из повторной постановки; cyclic DMA с перезаписью пользовательской записи не используется.

## 23.10.2026 — скорость просмотра и положение триггера

- DEBUG формирует запись после реального DMA completion без побайтового чтения отбрасываемых кодов из coherent-памяти. Периодические формы заполняются повторением периода; отдельная форма NOISE сохраняет генерацию каждого отсчёта. Шум к периодическим формам не добавляется.
- Экстремумы, суммы и суммы квадратов считаются в целых кодах АЦП; перевод в вольты выполняется для результатов. FFT выключенного представления не рассчитывается. Таймер GUI учитывает рисование и вывод внутри периода кадра.
- Программный триггер выбирает фронт после необходимой предыстории, если экранный интервал помещается в блок. Координата маркера вычисляется из того же интервала, что график, включая PAN/ZOOM и удерживаемую запись STOP. Аппаратный кольцевой pretrigger этим не реализован.

## 23.10.2026 — адаптивная запись и ROLL

- TIME управляет глубиной записи 10K/50K/100K/500K/1M точек на канал, по умолчанию 100K. Частота выбирается автоматически под интервал; верхний предел остаётся 200 MSa/s. Развёртка расширена до 10 нс/дел…5 с/дел. AUTO длиннее 100 мс/дел использует ROLL, NORMAL/SINGLE сохраняют событийный захват.
- FPGA равномерно прореживает уже считанные пары каналов; такты и входные регистры АЦП продолжают работать. На максимальной частоте используются обе ветви A/B, на остальных — равномерно выбранные пары A. Длина DMA-пакета адаптируется, чтобы медленные развёртки получали порции сигнала не реже 25 раз в секунду. Это частота поступления блоков по расчёту, не измеренная частота GUI.
- ABI/register/header version 3 отделяет новую конфигурацию от старого фиксированного потока. Реконфигурация разрешена только без lease. Общий модуль истории удерживает непрерывные отсчёты, освобождая DMA сразу после копирования; пропуски очищают историю. Отдельные снимки сохраняют STOP и последний успешно запущенный NORMAL/SINGLE.
- Программа обрабатывает свежую историю с интервалом около 40 мс, не задерживая UI ожиданием полного длинного экрана. FFT вычисляется только при включении. Результат 10 Гц и выше на плате проверяется отдельно для конкретных режимов.
- OLED меняет страницу только по K1. Ошибки сохраняются на Errors, пропущенные READY-блоки предпросмотра остаются счётчиком SKIPPED на Capture. Температурные страницы продолжают общую нумерацию.
- По прямому указанию владельца обязательное резервное копирование QSPI удалено из UART-обновления. Сохраняются проверка структуры образов, SHA-256 переданных файлов, ограничения разделов и проверка записанного содержимого. Существующие пользовательские копии не удаляются.

## 23.10.2026 — повторная настройка частоты DMA

- Остановка сначала завершает активный DMA-пакет, затем отключает и сбрасывает входной поток. После распространения reset выполняется повторный сброс DMA: он удаляет слова, которые S2MM успел принять между первым сбросом и отключением источника. Иначе начало следующего буфера могло содержать остаток предыдущего пакета вместо заголовка.
- На плате повторное открытие и настройка проверены на 200M, 100M, 1M, 10K и 100 Sa/s. Во всех режимах два трёхсекундных прогона завершились без ошибки заголовка; закрытие заняло 14–89 мс. На 200 MSa/s доставлено 399,42–399,44 МБ/с, с двумя пропущенными читателем READY-блоками в каждом прогоне при проверке удерживаемого lease. Это короткий тест обмена, не проверка аналоговой точности или длительной записи без потерь.

## 24.10.2026 — обработка больших записей

- При времени обработки больше периода DMA-блока AUTO накапливал очередь и терял непрерывную историю. Перед следующим кадром добавлен разбор накопленных блоков с ограничением партии; NORMAL/SINGLE продолжают проверять каждый блок. Увеличение очереди само по себе не использовалось как исправление.
- Шум генерируется целочисленно с прежними значениями кодов; константы преобразования вынесены из цикла, неиспользуемые таблицы не рассчитываются. На ARM NEON ускоряет точные суммы, квадраты, min/max и подсчёт пересечений. Проверка на Zynq сравнивает результаты с независимым скалярным расчётом на 1 000 003 точках, включая хвост вектора, переход через порции накопления, отрицательный и нулевой gain.

## 24.10.2026 — полный кадр обычной развёртки и шум DEBUG

- Обычная развёртка публикуется только после накопления полного непрерывного экранного интервала, включая основной интервал при ZOOM. AUTO не публикует частично заполненную историю; после разрыва и расширения масштаба действует то же условие. Ожидание не блокирует GUI. FORCE также ждёт полного интервала, ROLL сохраняет постепенное заполнение.
- Периодические формы DEBUG получают псевдослучайный шум −1/0/+1 код после копирования периодов. Шум зависит от аппаратного sequence и позиции отсчётов, поэтому не повторяется с каждым периодом формы; та же запись в STOP неизменна. Значения АЦП и самостоятельная форма NOISE не меняются. Публикация по-прежнему требует реального завершения DMA.

## 24.10.2026 — уровни АЦП и стартовая проверка

- По требованию владельца HDMI DEBUG показывает ADC CH1/CH2, а OLED использует свободную строку существующей страницы Capture: `CH1:… CH2:…`. Источник — последняя пара реального DMA-блока до SIMULATION; значения передаются через snapshot метрик и локальный status IPC версии 3. После ошибки или трёх секунд без новых данных показываются прочерки. Отдельная страница OLED и отдельная утилита чтения не нужны.
- До первого кадра осциллографа проверяются настроенная USB-панель, чтение и запись карты данных, затем АЦП. Сенсор необязателен и подключается в рабочем цикле GUI. Ошибка обязательной проверки сохраняет отдельный диагностический экран на HDMI/OLED и не допускает запуска осциллографа и remote API. Существующий интерфейс и настольные источники сохраняются.
- Стартовый делитель меняет физические CLK_A/CLK_B от 1,5625 до 100 МГц на ветвь, сохраняя приёмный домен 100 МГц и выдавая только стабильные пары A/B. При старте и новом open выбран медленный режим; CONFIGURE возвращает номинальные такты и обычное прореживание. Карта регистров — 4, ID — `0xADC40000`; driver ABI и заголовок блока остаются версии 3.
- Четыре DMA-блока каждой ступени проверяют обмен и сырые коды четырёх ветвей. Постоянный предельный код блокирует запуск с указанием частоты и ветви; это не объявляется доказательством отключённого АЦП. Без известного аналогового воздействия нельзя подтвердить все линии и точность по одному постоянному значению. Условия и границы — [STARTUP_CHECKS.md](STARTUP_CHECKS.md).

## 24.10.2026 — ожидание восстановления при запуске

- После ошибки стартовая проверка повторяется через секунду, пока приложение работает. ## 24.10.2026 — вертикальный масштаб реального АЦП

Учёт щупа ×10 изменяет напряжение без изменения высоты следа. Коэффициенты рассчитаны по схеме и не объявляются калибровкой незавершённого тракта.

## 24.10.2026 — подпись развёртки и управление TIME с панели

- По требованию владельца подпись времени содержит только масштаб, без суффикса ROLL. Режим прокрутки и условия его включения сохраняются.

## 24.10.2026 — устойчивый выбор фронта триггера

- Шум возле уровня на спадающем склоне мог создавать локальный положительный переход, который принимался за RISING. Поиск фронта теперь сначала вооружается на расстоянии двух кодов с противоположной стороны уровня. Сам момент триггера остаётся пересечением заданного уровня; для FALLING действует симметричное условие.
- Перед началом разрешённого интервала восстанавливается состояние по доступной истории. Пересечения до этого интервала расходуют вооружение, чтобы не принять следующий шумовой возврат. Общий обработчик принимает ширину гистерезиса явно; аппаратный pipeline использует два кода, нулевая ширина сохраняет прямое пересечение для других вызовов.

## 24.10.2026 — отзывчивость, плотность, FFT и Peak Detect

- Расчёты записи, FFT и карты плотности выполняет processing worker. Готовые кадры передаются через три слота: смена владельца короткая, копирование карты не удерживает mutex настроек и метрик. UP панели классифицируется по длительности из меток STM32, без повторной проверки времени задержавшегося GUI.
- Coloring считает исходные отсчёты по пикселям, не расширяет след и не считает заполненный min/max плотностью. STOP сохраняет запись; ZOOM получает плотность из выбранного участка той же записи.
- FFT использует до 64K последовательных отсчётов. Общая шкала имеет начало 0 Гц и логарифмический участок; размер преобразования передаётся в GUI для DF, подписей и курсора.
- При аппаратном прореживании два равномерных отсчёта сохраняются вместе с min/max всех A/B за их интервал. Это не цифровой антиалиас-фильтр и не замена исходных данных для FFT. Максимальный поток остаётся 400 МБ/с по расчёту: 200 MSa/s × 2 байта без прореживания либо 100 MSa/s × 4 байта с экстремумами. ABI 4, регистры 5, заголовок 4, формат 2, ID 0xADC50000.
- Индикатор батареи использует переданные STM32 мВ до делителя 1:2. Временная шкала одной Li-ion ячейки задана в battery_level.h; свежесть — 3 секунды, при отсутствии данных уровень неизвестен.
- Индикатор батареи показывает только заполнение, без числа. SIMULATION переключается одним нажатием FUNC; OFF/ON видны одновременно. Формы генератора и все пять длин записи видны целиком, без обрезания последнего варианта.
- При увеличении остановленной записи min/max не растягивается в промежутках между редкими отсчётами. Их значения соединяются линиями; в coloring синее соединение не входит в статистику попаданий, а реальные точки сохраняют цвет плотности.

## 24.10.2026 — единое отображение Peak Detect при увеличении

- Отключение всей огибающей при переходе через один отсчёт на пиксель давало резкую смену вида между соседними масштабами. Для записи 200 kSa/s это происходило между 1 мс/дел и 500 мкс/дел.
- Каждый сохранённый интервал экстремумов теперь отображается одной вертикальной меткой в его центре. В общей функции waveform_view задан размер интервала и отдельный callback его границ; приложение захвата задаёт два отсчёта. При сжатии совпавшие колонки объединяются, при увеличении метки расходятся без растягивания в широкие блоки и без полного исчезновения на пороге.
- Равномерные отсчёты по-прежнему соединяются линией, coloring считает только реальные попадания, а min/max измерений учитывает все пересекающиеся интервалы. Центр метки не выдаётся за измеренный момент экстремума. Форматы записи и FPGA не меняются.

## 24.10.2026 — соединение пропущенных экстремумов

- По выбранному владельцем варианту вертикальные метки заменены непрерывной ломаной через пропущенные min/max. Если сохранённая линия уже охватывает экстремумы, её изображение не меняется. Общая геометрия находится в waveform_view; захват передаёт границы двухотсчётных интервалов прежним API.
- При одном пропущенном пике используется только он, без переноса противоположного экстремума. Небольшая поправка располагается около ближайшего сохранённого экстремума; доминирующий скрытый пик соединяется с концами интервала треугольником. Для двух пропущенных экстремумов используются две вершины, их порядок следует направлению между концами. Время и порядок пиков неизвестны, поэтому это условная интерполяция для отображения.
- Диапазон ломаной считается по пересечению с колонкой экрана. Полные интервалы объединяются сразу, без создания промежуточного массива на всю запись; частичные интервалы обрабатываются геометрически. Один алгоритм работает по обе стороны масштаба один отсчёт на пиксель.
- Интерполяционные вершины не участвуют в FFT, среднем, RMS, частоте и coloring. Эти расчёты используют равномерные отсчёты; min/max и Vpp дополнительно учитывают сохранённые экстремумы. Отсутствие алиасинга само по себе не гарантирует точную форму при нескольких отсчётах на период.

## 24.10.2026 — толщина следа и видимый шум

- Одинаковая яркая заливка каждого min/max превращала шум в толстый штрих. Карта реальных попаданий теперь рассчитывается и для обычного следа: без COLORING она управляет яркостью цвета канала. В COLORING прежняя цветовая шкала сохраняется. Графическая линия имеет толщину в один физический пиксель, дополнительный контур убран.
- Пропущенные Peak Detect экстремумы больше не подменяют временные отсчёты ломаной с условными вершинами. Они показаны самостоятельной полосой известного интервала. Слабый пропущенный размах отображается слабее, сильный даёт видимую стенку; через сильный недоразрешённый интервал отсчёты не соединяются ложной кривой. Полоса не создаёт density hits и не скрывает малые выбросы.
- Получение записи, генератор, FFT и измерения сохранены. Карта яркости обрабатывается тем же worker и передаётся через существующие слоты кадров; GUI не сканирует аппаратную запись. STOP и ZOOM используют прежнюю удержанную запись и пересчитывают яркость из неё.
- По уточнению владельца увеличенная запись показывает соединённую кривую без ступенчатой подложки. Полоса Peak Detect ослабевает логарифмически между четырьмя и половиной отсчёта на пиксель; на этом же диапазоне возвращается яркость линии. Широкий переход не привязан к конкретному TIME/div и учитывает Fs самой записи. Закрашивается только не представленный отсчётами размах, что также убирает лишнюю работу рендерера на длинных записях.

## 24.10.2026 — непрерывные фронты без ложного периода отображения

- Соединение одного опорного отсчёта на колонку создавало собственный алиасинг изображения: при переходе 5→10 мс/дел вместо сжатого меандра появлялся крупный ложный период. Подавление опорной линии рядом с Peak Detect оставляло на фронтах отдельные попадания. Для аппаратной записи опорная ломаная заменена картой покрытия всех последовательных отрезков исходной записи.
- Общий растеризатор пересекает каждый настоящий отрезок с временными границами колонки и собирает покрытие строк через разностный массив. Стоимость не зависит от длины вертикального фронта в пикселях. Обработчик передаёт готовую карту через существующие слоты; GUI не обходит запись и не выбирает редкие точки. При сжатии несколько настоящих фронтов дают стенку, при увеличении остаются те же отсчёты с линейным соединением.
- Карты покрытия и реальных попаданий разделены. Покрытие управляет только видимостью соединения и не меняет счётчики COLORING. В COLORING синее соединение имеет нижнюю границу яркости, чтобы редкий фронт оставался видимым. Peak Detect сохраняет самостоятельную полосу; её маска не стирает известный отрезок. FFT, измерения, частоты захвата и генератор не меняются.

## 24.10.2026 — яркость соединения при сжатии

- Ограничение покрытия уровнем 160 из 255 при плотности более одного отсчёта на пиксель делало кривую тусклой и меняло её яркость при увеличении. Максимальное покрытие колонки теперь всегда получает 255; остальные ненулевые уровни — `96 + 159 × sqrt(count / peak)`. Нулевое покрытие остаётся прозрачным. Редкие переходы видны лучше, а распределение шума сохраняет градации.
- Нормировка не зависит от TIME/div или числа отсчётов на пиксель. Геометрия соединения, реальные счётчики попаданий, цветовая шкала COLORING, аппаратные экстремумы, FFT и измерения не изменяются.

LOW/MEDIUM/HIGH теперь используют общее симметричное среднее по 5/17/65 сохранённым отсчётам перед построением всех представлений выбранного канала. Дробные значения сохраняются до проекции в пиксели; окно задаётся в отсчётах и при STOP/ZOOM не меняется. Производное представление не подменяет исходную запись.

Настройка проходит через CaptureRequest/CaptureView и увеличивает ревизию обработки, поэтому в STOP пересчитывается та же запись. OFF восстанавливает её исходное представление. После смены фильтра старая история следа очищается. Аппаратные измерения, FFT и триггер читают исходные отсчёты; временной фильтр не применяется к Peak Detect экстремумам, для которых неизвестно время внутри интервала.

На плате используется JFFS2 существующего раздела settings, на ПК — файл рядом с программой. Сигнальные записи, телеметрия и промежуточные значения EDIT не сохраняются. ## 25.10.2026 — большой FFT и калибровка АЧХ каналов

- В FFT сверху остаётся малый временной график, снизу — большой спектр. Общая геометрия задаёт положение, высоту и преобразование координат курсоров в обоих frontend. Спектр передаёт 1024 частотные группы вместо 128; между исходными частотами интерполируется амплитуда без превышения пиков. Частотные подписи вынесены над графиком, отдельно от панели измерений. Размер FFT выбирается по имеющимся отсчётам видимого интервала до 1M; при обработке 1M исходных отсчётов используется 524288. Частотный шаг самого FFT не подменяется экранным разрешением.
- TIME в ZOOM меняет масштаб в том же направлении, что обычная развёртка; направление перемещения окна также развёрнуто по указанию владельца.
- CALIBRATE заменяет прежнюю демонстрационную центровку канала режимом накопления относительной АЧХ. Выраженный спектральный пик измеряется до коррекции и фильтра. Первая точка задаёт опорную амплитуду, близкие частоты уточняют существующие точки. RUN/FUNC управляют набором; коррекция включается отдельно.
- ChannelResponse хранит частотные точки и выполняет амплитудную коррекцию производной записи через общий FFT. Время исходных отсчётов и триггер не меняются, фазовая калибровка не заявляется. Исправленная копия используется для кривой, амплитудных измерений и FFT; обычный FILTER применяется после коррекции и сохраняет прежний смысл.
- Реальные и симулированные АЧХ CH1/CH2 хранятся четырьмя независимыми кривыми вне содержимого пресетов. SIMULATION перебирает частоты и моделирует ФНЧ; её кривая не заменяет реальный тракт. Документ настроек версии 2 сохраняет кривые и читает предыдущую версию 1.
- Служба запуска распознаёт оставшийся после аварийного завершения PID-файл по /proc/PID/exe и не принимает его за работающий GUI. После этой проверки удаляет оставшийся управляющий сокет, который иначе мешает повторному запуску.

## 25.10.2026 — доступность настроек и независимый вывод интерфейса

- Доступность строк и отдельных вариантов выводится из состояния приложения при обновлении меню. Серые элементы исключены из касаний, активации и обхода FUNC; пустые слоты STARTUP/LOAD, коррекция без АЧХ и действия без открытого файла не выполняются. SETUP больше не содержит TIME. FILES и DISPLAY → LAYOUT дают с панели доступ к сохранению, просмотру, удалению, размещению измерений и высоте разделённых окон.
- Энкодер над кнопкой управляет её открытым меню: CH1/CH2, TIME для курсоров и TRIGGER. FUNC остаётся общим. Та же маршрутизация обслуживает навигацию, EDIT, применение и BACK; на страницах АЧХ сохраняется принадлежность каналу. На STM32 энкодер открытого меню канала временно переводится в передачу дельт вместо локального переключения диапазона.
- Сохранённая история PERSISTENCE действительно рисуется перед текущим захватом. Возраст задаёт затухание, смена геометрии очищает историю. След прошлого захвата не пополняет счётчики исходных попаданий COLORING. Старые слои сначала объединяются в карту прозрачности, затем смешиваются с изображением одним проходом; карты кривой выводятся небольшими плитками для локальности CPU-кеша.
- ScopeRenderer принимает неизменяемые снимки экранного состояния. Отдельный поток строит график каналов, другой компонует меню, значения и курсоры поверх последнего готового графика и выводит изображение. Состояние растеризатора и кеш скруглений принадлежат потоку. Обработка записи, FFT и фильтрация остаются в обработчике захвата; интерфейс использует его готовые измерения.
- Большие готовые карты передаются по аренде слота, без копирования в цикле ввода. Обработчик не перезаписывает занятый слот; новое представление можно пропустить, но нельзя ожидать завершения рисования в GUI. Необработанные запросы рисования объединяются до последнего состояния. Вывод Linux framebuffer/DRM выполняется вне цикла ввода; SDL и WinAPI показывают готовые буферы согласно требованиям своих оконных API. Явное сохранение BMP ожидает актуального графика отдельно от обычного обновления экрана.
- После замеров на плате приоритет только потока построения графика понижен: nice 5 на Linux, BELOW_NORMAL на Windows. Ввод, вывод интерфейса и получение аппаратных данных сохраняют обычный приоритет; affinity не задаётся. Для CPU-растеризатора Zynq включены те же O3/NEON, что уже используются обработчиком записи.
- Жёлтый HOLD показывает ожидание триггера. Принятому источником захвату присваивается метка, которая проходит через обработку и построение графика до вывода. RUN включается при принятии записи и сохраняется до фактического показа графика с этой меткой; после показа возвращается HOLD до нового срабатывания. Таймера и ожидания готовности FFT для включения RUN нет. На аппаратном захвате SINGLE останавливается после показа принятой записи. STOP и BACK имеют прежний смысл.

## 25.10.2026 — выключенные реле и подтверждение фронта триггера

- SET_SCALE/SCALE со значением 0 задаёт и подтверждает OFF, отдельно от обычных масштабов. Штатная STM32 начинает с отпущенными катушками обоих каналов; положительный абсолютный масштаб включает канал. Отдельная сборка STANDALONE_DEBUG сохраняет исходно включённые каналы для отладки без GUI. Выключение сохраняет выбранную ступень, шаги выключенного канала передаются GUI без изменения GPIO. GUI восстанавливает ON/OFF и выбранные диапазоны после reconnect/сброса и игнорирует запоздалые подтверждения предыдущего состояния. Для номинального коэффициента выключенного входа используется маска 000 и нижнее плечо 510 Ом.
- Триггер подтверждает переход от одной стороны шумового зазора до другой; короткий возврат к исходной стороне не является фронтом. Метка остаётся на исходном пересечении заданного уровня. Ненулевой параметр гистерезиса задаёт нижний предел: автоматический зазор равен тройной медиане модулей соседних разностей, ограниченной четвертью размаха и расстоянием от уровня до наблюдаемых границ. Минимум аппаратного поиска — два кода АЦП. При нулевом параметре сохраняется прямое пересечение порога. Эта защита не фильтрует запись и не меняет FFT, измерения или отображаемый сигнал.
- Для поиска фронта применяется выбранный FILTER канала, чтобы направление соответствовало видимой кривой при высокочастотной помехе. Фильтрация выполняется в рабочем потоке над копией кодов; исходная запись, FFT и измерения не меняются. История persistence очищается при изменении источника, направления, уровня или режима триггера, чтобы старые захваты не накладывались на новое условие запуска.
- HIDE в MEASURE включён непосредственно в тот же обход FUNC, что и каталог измерений и CLEAR ALL. Альтернативный путь через DISPLAY не заменяет доступность самой кнопки. Значения измерений используют постоянную ширину поля для выбранного шрифта; текущие цифры и единицы не перестраивают столбцы.
- ZERO / NOISE в калибровке собирает четыре свежие записи замкнутого входа, сохраняет среднее, RMS шума и коэффициент преобразования АЦП отдельно для реальных и имитируемых CH1/CH2. При сборе АЧХ применяется оценка шумовой мощности окна Ханна; исходный сигнал не исправляется этой оценкой. Смена аппаратной ступени или щупа требует нового измерения. Документ настроек версии 3 сохраняет эти данные и читает прежние версии.
- START продолжает существующую АЧХ после STOP. Только красная CLEAR POINTS удаляет точки; измеренный ноль и шум остаются. Новый замер нуля недоступен до удаления прежних точек. Проверки на ПК и проверки на устройстве разделены в TESTING.md.

## 25.10.2026 — независимые калибровки канала

- CALIBRATE содержит три раздела: ZERO, NOISE, FREQUENCY RESPONSE. У каждого собственные запуск и сброс; действия выполняются FUNC и энкодером выбранного канала. BACK возвращает через CALIBRATION в настройки канала. Недоступные сбросы серые, доступные выделены красным.
- Ноль вычитается из метаданных производного представления записи и поиска триггера; исходные коды и номинальный zero_code источника неизменны. Изменение и сброс нуля пересчитывают STOP, измерения и график из прежней записи. Измерение нуля и шума всегда использует исходный ноль, без уже применённой поправки.
- Ноль и шум имеют независимые признаки готовности и коэффициенты преобразования. Сброс каждой калибровки сохраняет две другие. Шум корректирует оценку амплитуды при сборе АЧХ; он не вычитается из временного сигнала. Настройки версии 4 читают версии 1–3; объединённый результат версии 3 переносится в независимые ноль и шум.

## 25.10.2026 — калибровка ступеней реле и подавление шума

- ZERO и NOISE автоматически обходят три рабочие аппаратные ступени, ждут подтверждения STM32 и собирают по четыре свежие записи. Исходный диапазон возвращается после завершения и отмены; промежуточные ступени не сохраняются как пользовательская настройка. Незавершённый проход не заменяет прежние результаты. RESET очищает выбранную калибровку на всех ступенях, сохраняя соседние.
- По измеренному RMS работает отдельное автоматическое сглаживание локальной дисперсии: окно 17 отсчётов, сохранение исходного отсчёта при дисперсии от девяти шумовых мощностей. Ручной FILTER применяется после него. Исходные отсчёты, FFT и измерения сохраняются; триггер использует ту же обработку. Сильные Peak Detect экстремумы более восьми RMS не скрываются автоматическим сглаживанием.
- Калибровки реальных и имитируемых каналов разделены по аппаратным ступеням. Версия настроек 5 читает версии 1–4 и переносит прежние результаты по коэффициенту преобразования. STOP выбирает поправку по коэффициенту сохранённой записи, а не по текущей подписи В/дел.

- Существующий документ настроек при ошибке чтения, повреждении или неизвестной версии остаётся без записи: автосохранение и SAVE не заменяют его значениями по умолчанию. Документ версии 5 читает предыдущие версии и переносит калибровки по коэффициенту ступени. При обновлении GUI не подменяются текущие настройки проверочным снимком.
- Постоянный раздел settings остаётся в последних 1 МиБ QSPI. Составной qspi.bin ограничен первыми 15 МиБ и не содержит области настроек; проверка release требует эту границу. UART-обновление по-прежнему пишет только boot и linux-fit.

## 25.10.2026 — назначение разрядов AD9288 и медленный диагностический захват

- Назначения всех 32 линий АЦП сверяются через цепочку «вывод AD9288 → сеть основной схемы → XS1 → CAM1 MINI → вывод Zynq», отдельно от логических имён A/B в FPGA. Для первого АЦП физические D3A и D5A подключены соответственно к N17 и W14. Исправление выполняется в XDC; исходные данные не маскируются и не сглаживаются для устранения перестановки битов.
- При делении encode приёмный такт остаётся 100 МГц. Положение фиксации пары учитывает полный возвратный путь такта и данных: `period/2 + 3` вместо `period/2 + 2`, с приведением по периоду. Нативный режим 100 МГц не меняет положение захвата. Регрессионная модель проверяет принадлежность A/B одному циклу при задержках 6 и 13 нс для всех семи частот; численные задержки модели не объявляются измерениями платы.
- Диагностические конфигурации FPGA загружаются только в RAM, с остановкой ADC DMA и VDMA. В штатный образ включаются подтверждённые исправления. Электрические настройки входов и выходов такта сохраняются, если сравнение на плате не показало существенной пользы от их изменения; остаточный шум не скрывается подменой битов.

## 26.10.2026 — поиск редких пачек на короткой развёртке

- В обычной развёртке история программного триггера содержит выбранную глубину записи и один полный payload DMA. Входящий блок не обрезается до поиска: это сохраняет события в начале блока и фронты, которым нужен участок после события из следующего блока. Разрывы по-прежнему сбрасывают историю; ROLL хранит выбранную глубину.
- AUTO, NORMAL и SINGLE проверяют события после каждого блока. Ограничение свободного хода AUTO до одного представления за 40 мс применяется после поиска; принятый триггер его обходит. После поиска сохраняется запись выбранной глубины вокруг события, с выравниванием пар Peak Detect. Размер payload и частота IRQ не меняются.
- Память истории и двух снимков увеличена на один максимальный payload каждый, рабочая память DEBUG прежняя: вместе 22 291 456 байт для отсчётов и экстремумов. Программные проверки и сборки не являются измерением задержки на устройстве.

## 26.10.2026 — постоянная составляющая при смене Time/div

- При снижении частоты ниже 200 MSa/s опорная точка FPGA формируется из среднего соседних A/B того же канала. Ранее выбиралась только A, поэтому различие нулей физических фаз давало скачок относительно полного потока A/B. Перенос остатка половины кода между выбранными парами исключает систематическое округление вниз. Полный поток 200 MSa/s и исходные min/max сохранены.
- Это двухточечное усреднение перед прореживанием с характеристикой |cos(πf / 200 МГц)|; оно не заменяет антиалиас-фильтр под эффективную частоту. Калибровка нуля, V/div, вертикальная позиция, масштабирование GUI и форматы BMP/CSV не меняются.

## 26.10.2026 — скорость экрана и устойчивые измерения времени

- История захвата стала линейной: поиск заимствует её без полного снимка, в общее кольцо копируется только принятая запись выбранной глубины. Отдельный processing worker удерживает собственную запись для STOP; медленная обработка не удерживает DMA. История, три записи и DEBUG занимают 22 097 152 байт для кодов и экстремумов.
- Поиск с фильтром расширяет только необходимое окно вокруг разрешённого интервала, восстанавливает предыдущую сторону гистерезиса и проверяет полный запас фильтра после подтверждения. Автоматическая полоса оценивается на текущем окне. Отображение фильтрует видимый участок с запасом; целочисленные суммы и квадраты кодов АЦП используются общей реализацией подавления шума.
- Карты выключенного канала не рассчитываются. Гистограмма яркости использует занятые ячейки, соединения обходят занятый вертикальный диапазон, ARM-растеризатор пропускает пустые блоки. Повторные заливки и композиция старого графика при приходе нового захвата исключены. Поток графика использует обычный приоритет: при непрерывном захвате прежний nice 5 приводил к длительному ожиданию CPU.
- FREQ/PERIOD/DUTY используют ту же обработанную кривую, что и экран. Общий детектор с триггером подтверждает переход через гистерезис, а время пересечения интерполируется. Оценка по целым согласованным периодам не считает шумовые пересечения отдельными периодами; незавершённые края исключены из duty. Недостаточные данные дают прочерк. Исходные амплитудные статистики и FFT сохраняются; числового сглаживания между кадрами нет.
- Remote `state` не инициирует рисование; время фактического вывода новой записи учитывается отдельно от её захвата. Изменения проверяются в RAM прибора с сохранением настроек; запись QSPI этим сеансом не выполняется.

## 26.10.2026 — напряжения Measurements и обработанная кривая

- Vpp/MIN/MAX, среднее и RMS используют обработанные равномерные отсчёты видимого интервала до сжатия в 1024 колонки. Нативные экстремумы расширяют MIN/MAX только через тот же источник, который передаёт их графику. При ручном FILTER не учитываются скрытые им нативные пики.
- Для ZERO/NOISE и оценки шума при калибровке АЧХ введены отдельные raw_mean/raw_rms из исходных отсчётов. Смена FILTER не меняет калибровочную статистику или FFT. Исходная запись и форматы экспорта сохранены.
- Подавление шумовой огибающей выполняется на каждом нативном интервале перед объединением. Наличие настоящего фронта в колонке или во всём измерительном окне не должно возвращать шумовые пики соседних интервалов.
- Vpp остаётся полным размахом с видимыми выбросами. Разность курсоров на полках меандра не подменяет экстремумы и может быть меньше Vpp. Числа пересчитываются из той же записи при изменении FILTER в STOP.

## 26.10.2026 — стоимость поиска между редкими посылками

- До выделения рабочего окна проверяются границы исходных и подавленных по шуму кодов. Порции по 256 отсчётов имеют полный запас общего фильтра; участки, которые заведомо не достигают нужных уровней, не требуют полной фильтрации записи. Симметричное среднее и подавление шума сохраняют значение внутри диапазона своих входов, поэтому проверка является необходимым условием, а не порогом по предполагаемой амплитуде UART.
- Поиск начинается у первого возможного перехода и пропускает проверенный префикс только при отсутствии незавершённого пересечения. Долгое пребывание внутри полосы по-прежнему требует восстановления исходной стороны и сохранения ранней метки пересечения. Выбранный фронт, уровень, holdoff, фильтрация графика и исходная запись не меняются.
- Remote state передаёт существующие счётчики блоков, пропусков, перезаписей и ошибку источника для проверки покрытия потока отдельно от частоты обновления экрана.
- Сохраняется coherent DMA allocation. Проба `dma_alloc_noncoherent` с синхронизацией только выдаваемого payload не улучшила покрытие потока на плате: затраты на cache maintenance превысили выигрыш от кешируемого чтения. Частота обновления редких посылок зависит также от пропусков DMA; программный поиск не гарантирует проверку всего входного потока при любой глубине и частоте.

## 27.10.2026 — предварительный отбор тихих блоков в ПЛИС

- PL считает min/max равномерных отсчётов двух каналов одновременно с передачей payload. Результат передаётся в резерве следующего заголовка с sequence, длиной, частотой и magic. Дополнительная ступень вычисления границ сохраняет исходную пропускную способность AXIS. Формат payload, ABI и версия основного заголовка сохранены.
- Адаптер разделяет выдачу закодированного DMA-пакета и распаковку выбранного диапазона в память вызывающей стороны. История освобождает место после проверки разрыва sequence/first_sample; промежуточная копия полного распакованного блока не нужна.
- Acquisition проверяет аппаратную сводку до чтения всего payload. Для любого выбранного фронта проверяются обе стороны гистерезиса в двух соседних блоках: без них фронт невозможен в сохраняемой истории. Это позволяет пропускать постоянный уровень с любой стороны порога, удерживая один контекстный блок. Событие, его предыстория и необходимый следующий блок проходят прежний фильтрованный детектор; запись 100K не заменяется экранными точками.
- При отсутствии пригодной сводки, глубине больше входного блока, ROLL, DEBUG, калибровке и FORCE используется полный путь. AUTO сохраняет периодический вывод без триггера. DMA остаётся непрерывным: эта ступень уменьшает чтение и обработку CPU, но не трафик PL–DDR.
- После потери заголовка со сводкой отставший пакет освобождается с учётом пропуска, чтобы восстановить смежную пару блоков без повторяющейся дорогой обработки устаревших payload. Разрыв не склеивается с историей. После принятия фронта поиск перевзводится на новых входных данных с учётом holdoff, а не на более позднем фронте уже проверенного DMA-блока. Обработка не распознаёт протокол сигнала и не использует параметры UART.
- Сырые экстремумы недостаточны при шуме и чередовании ветвей A/B: одиночные исходные выбросы могут пересекать порог, хотя обработанный канал его не достигает. PL дополнительно считает точные целочисленные суммы и дисперсии центрированных окон из 17 representative-отсчётов. MMX2 передаёт границы средних, максимум дисперсии и raw-экстремумы с задержкой двух блоков. CPU использует общую с подавлением шума формулу для консервативной оценки диапазона; сигнал и фильтр не заменяются другим алгоритмом. При отсутствии NOISE остаются сырые границы. Для удержания контекста и двух ожидающих payload требуется не более четырёх DMA leases, включая новый заголовок.
- GUI подтверждает pipeline фактически показанный capture_id. До двух принятых записей проходят обработку и показ параллельно; потребитель получает следующий кадр только после показа предыдущего. Готовый кадр не заменяется новым. Если обе стадии заняты, acquisition продолжает выдавать/возвращать DMA-блоки и удерживает свежую предысторию без нового поиска; при записи длиннее входного блока история продолжает заполняться полностью. После освобождения стадии поиск перевзводится на новом интервале с запасом центрированного фильтра и с учётом holdoff. Эти интервалы учитываются отдельным счётчиком блоков deadtime; они не выдаются за проверенный на триггер поток. ROLL, DEBUG, калибровка и FORCE сохраняют свои пути обработки.
- Payload ограничивается минимальной степенью двух, вмещающей выбранную запись, при прежнем потолке размера и длительности блока. Для 100K это 131 072 эффективных отсчёта на канал: 256 КиБ при 200 MSa/s и 512 КиБ с Peak Detect. Поиск не должен распаковывать 262 144–524 288 отсчётов ради записи 100K. При восстановлении после разрыва используются уже находящиеся в очереди заголовки со сводкой предыдущего блока; отдельного накопленного состояния границ нет.
- Для шумного входа независимые границы MMX2 слишком широки. MMX3 добавляет поточечную аппаратную проверку возможности достижения LOW/HIGH того же Wiener-результата. Уровень и интервал мощности шума передаются через свободные старшие линии capture GPIO; optional SET_PROBE сохраняет совместимость со старым ядром и PL. Проверка использует обе границы мощности и ветвь сохранения импульсов, округляется в сторону дополнительных кандидатов и не изменяет отсчёты. Точное условие и время пересечения остаются в общем программном детекторе; протокол входного сигнала не распознаётся и скорость UART не участвует.

## 27.10.2026 — перенос численной обработки в ПЛИС

- Общий модуль `signal_wiener` принимает код центра и точные целочисленные статистики окна 17 точек. Он вычисляет сам обработанный отсчёт, а не только необходимое условие достижения порога. Шумовая мощность задаётся Q16.16, выход — Q8.16; вес Wiener вычисляется конвейерным делением с 24 дробными разрядами. Сохраняются ветви среднего при variance ≤ noise и исходного отсчёта при variance ≥ 9×noise. Каждый такт может принимать новый отсчёт, паузы и reset проходят через конвейер явно. Модуль не зависит от GUI, канала, частоты АЦП и протокола входного сигнала.

## 27.10.2026 — аппаратный триггер и полное усреднение интервала

- ПЛИС определяет первый разрешённый фронт после Wiener и ручного FILTER. Атомарный набор настроек передаётся через AXI-Lite; TRG1 удерживает ID взвода и номер события до нового взвода. Acquisition использует этот номер без повторного поиска на ARM и собирает полную запись выбранной глубины. Предыстория покрывает задержку заголовка и posttrigger; утраченная история учитывается отдельно и вызывает новый взвод. Measurements, FFT и проекция принятой записи пока остаются программными.
- Прореженный равномерный поток усредняет все исходные A/B внутри каждого интервала. Выбор отдельной пары пропускал высокочастотную составляющую с разным alias на разных развёртках. Восьмиступенчатое деление сохраняет пропускную способность; перенос остатка предотвращает смещение постоянного уровня. Нативные min/max сохраняются независимо от усреднения. Это прямоугольный фильтр с известной частотной характеристикой, а не идеальное подавление всех частот выше Найквиста.

## 27.10.2026 — измерения записи через HP1

- Численное ядро ПЛИС повторно читает выбранный интервал записи из DDR и выдаёт экстремумы, среднее, RMS, частоту и duty. Алгоритмы общие с настольной моделью; аппаратный вариант использует float и точные центрированные исходные моменты. Блочный доступ отделён от арифметических циклов, состояние между блоками сохраняется. Нулевая частота выборки отключает только временные измерения.
- HP1 обслуживает это ядро независимо от захвата на HP0 и HDMI на HP2. Linux передаёт входы и коэффициенты через отдельный синхронный ioctl и ожидает IRQ; аппаратные возможности проверяются через прежний capture GPIO до первого MMIO. Coherent arena принадлежит устройству и не освобождается закрытием fd после незавершённого аппаратного обращения. Подключение вычислений к GUI выполняется отдельным этапом.

## 27.10.2026 — аппаратные измерения в обработчике кадра

- Численный интерфейс SignalAnalyzer отделяет выбор исполнителя от кривой, GUI и транспорта. Аппаратный адаптер передаёт выбранные исходные точки либо физические значения в DDR replay; raw mean/RMS остаются отдельными от измерений видимой обработанной кривой. В проходах, где временные измерения не используются, поиск периодов отключён.
- Отсутствие совместимого ядра оставляет прежний программный источник. Ошибка уже выбранного аппаратного исполнителя прекращает обработку кадра и отмечает source_error, без показа старого результата как нового и без скрытого вычисления на CPU. Фильтрация принятой записи, native Peak Detect, FFT, коррекция АЧХ и проекция требуют следующих этапов переноса.

## 27.10.2026 — перекрытие расчёта ПЛИС и экранной проекции

- BEGIN фиксирует вход в private coherent arena и запускает аппаратный проход, FINISH забирает результат после IRQ. Между ними обработчик кадра готовит проекцию исходной кривой; кадр публикуется только с завершёнными измерениями. Синхронный MEASURE сохранён как композиция тех же операций.
- Дескриптор владеет одной незабранной задачей, повторный запуск отвергается даже после аппаратного завершения. Закрытие дожидается задачи, тайм-аут отсчитывается от запуска; память остаётся за устройством, чтобы поздний AXI master не обращался к освобождённому буферу. Ошибки не скрываются переключением вычислений на CPU.

## 27.10.2026 — полная аппаратная запись до массовой распаковки

- Если глубина больше одного payload, сборщик TRG1 сначала удерживает достаточную смежную цепочку encoded DMA leases, затем декодирует запись. Частичная распаковка каждого поступления могла занимать дольше периода payload и бесконечно сбрасывать недобранную историю. Условие готовности учитывает смежную декодированную историю и проверяет sequence, абсолютные номера, Fs и формат пиков.
- AUTO и FORCE используют этот же механизм; накопление не считается отбрасыванием сигнала. Поиск фронта остаётся аппаратным. Прежний источник и специальные режимы сохраняют свои пути, лимит удерживаемых leases не увеличен.

## 27.10.2026 — общий фильтр записи с ограниченной рабочей памятью

- Wiener и ручной FILTER используют SignalNumber: double в настольной модели, float для синтеза. Правила окон, обработки NaN и сохранения фронтов общие.
- API signal_filter_trace обрабатывает плитки по 256 отсчётов с суммарным соседним контекстом обеих стадий. Не требуется промежуточный массив размером со всю запись; результат выражен в физических единицах.

## 27.10.2026 — Wiener/FILTER принятой записи в ПЛИС

- Ядро DDR replay выполняет общий signal_filter_trace, возвращая физические значения после Wiener и выбранного FILTER. Плитки сохраняют полный соседний контекст; весь промежуточный массив не хранится в BRAM.
- FILTER_RECORD копирует вход в owned coherent arena 16 MiB и возвращает выход после IRQ под той же блокировкой. Capability bit 4 отделяет расширенную операцию от прежнего ядра; старый bitstream не получает обращений к новым регистрам.
- Обработчик передаёт фильтрацию аппаратному executor. Ошибка активного расчёта останавливает обработку, программной подмены нет. Прежнее ядро и настольные источники сохраняют свои программные фильтры.

## 27.10.2026 — ограниченные индексы аппаратной записи и конвейер окон

- SignalIndex выбирает uint32_t для DDR replay и size_t для обычных источников. Ограничение 1M относится к аппаратному API; моменты АЦП остаются 64-битными, дробные интервалы считаются после вычитания целых позиций.
- Сдвиг Wiener/FILTER выполняет одно добавление и одно удаление. Константные обратные размеры окон 1..65 убирают зависимость итераций через переменное деление. Порядок накопления и правила фронтов сохраняются.

## 27.10.2026 — единый интерфейс DDR replay

- Загрузка кодов, физических значений и сохранение результата объединены в record_memory. Плиточные фазы ядра последовательные; отдельный арбитраж трёх AXI masters не требуется.
- SmartConnect оставлен с одним входом для согласования ширины и AXI4/AXI3 с HP1. Частота, карта управления и контракт драйвера сохраняются; захват и HDMI используют прежние HP0/HP2.

## 27.10.2026 — разрядность локального окна фильтра

- Количество элементов Wiener/FILTER хранится в uint8_t: предел полного окна — 65. Это не длина записи и не её индекс.
- Байтовая сумма Wiener ограничена uint16_t. До удаления уходящего отсчёта она не превышает 18×255=4590; сумма квадратов сохраняет прежнюю разрядность. Ограничения устраняют лишнюю широкую арифметику в управляющем пути.

## 27.10.2026 — стадии сравнения float

- FCmp в HLS получает задержку 3, разделяя сравнение и управляющую логику регистрами. Частота ядра остаётся 100 МГц.
- Размер RTL-адаптера AXI отделён от длины задания: depth=4096 соответствует ограниченному стенду, runtime и UAPI сохраняют записи до 1M.

## 27.10.2026 — классификация аппаратного float

- Общая проверка signal_number_finite использует экспоненту binary32 для float и стандартный isfinite для настольного double. Она не зависит от различия флагов Windows fpclassify и библиотеки HLS.
- Фильтры сохраняют разрыв только в его исходной точке; недопустимые параметры задания отвергаются в том же аппаратном ядре.

## 27.10.2026 — непрерывная ширина ROLL

- В RUN окно ROLL следует за концом истории независимо от положения триггера. В STOP оно ограничено реальными отсчётами сохранённой записи.
- После разрыва последовательности новая непрерывная история заменяет показанную только при не меньшем покрытии времени. Начальное заполнение остаётся постепенным, но готовая кривая не схлопывается до короткого хвоста.

## 27.10.2026 — проект Vivado в Git

- oscill.xpr, исходная блок-схема, wrapper и необходимые локальные IP хранятся в Git и открываются в Vivado без предварительной сборки. Кеши, промежуточные проекты, bitstream и результаты трассировки исключены.
- Сборка открывает сохранённый проект; настройки и соединения изменяются в его GUI. Отдельное Tcl-описание той же схемы удалено. Исходный C-код HLS обновляется вместе с опубликованным RTL-пакетом IP.
