# Стартовая проверка Zynq

Штатный запуск `scope_preview --adc DEVICE` выполняет проверки до открытия
remote socket и первого кадра осциллографа. HDMI и OLED показывают этап.
При отказе показываются `STARTUP FAILED`, конкретная причина и `GUI NOT STARTED`.
Через секунду приложение повторяет проверку. Когда все проверки проходят,
осциллограф запускается автоматически, без перезапуска службы или платы.
Настольные источники DEMO, RAW DEMO и FILE аппаратную проверку не запускают.

## USB и карта данных

- Для заданного `--serial` ожидается корректный пакет существующего протокола
  панели STM32. Открытого tty без ответа недостаточно.
- Сенсор `--touch` необязателен: его отсутствие или отказ не задерживает
  запуск GUI. После запуска приложение ищет сенсор каждые 500 мс; при
  появлении подходящего устройства подключает его, а после отключения
  продолжает работу и возобновляет поиск. При открытии проверяются реальные
  evdev-возможности и диапазоны координат.
- Одна попытка ожидания USB-панели ограничена шестью секундами. При отказе
  попытки продолжаются. Отключённые в конфигурации интерфейсы не объявляются
  неисправными.
- При `--require-data-device` каталог данных должен находиться на
  смонтированном блочном устройстве. Проверка создаёт собственный небольшой
  файл, записывает его, выполняет fsync, читает и сравнивает данные,
  затем удаляет файл и синхронизирует ФС. Существующие файлы не меняются.
  Отсутствующая карта, read-only и ошибки чтения/записи блокируют запуск.

## АЦП

Перед проверкой нет программной подмены сигнала. Физические CLK_A/CLK_B
начинают с 1,5625 МГц на ветвь и последовательно переключаются на 3,125;
6,25; 12,5; 25; 50; 100 МГц. Это заданные частоты деления исходных 100 МГц,
а не измерение частотомером. Минимальная частота преобразования AD9288
по [datasheet Rev. C, таблица 1](https://www.analog.com/media/en/technical-documentation/data-sheets/AD9288.pdf)
составляет 1 MSPS. Номинал 100 MSPS относится к версии -100.

FPGA делит именно сигналы encode на выводах; приёмные регистры и AXIS
остаются в прежнем домене 100 МГц. На медленных режимах выдаётся одна
стабильная пара A/B за физический период. Заголовок содержит соответствующую
удвоенную частоту на канал. Прореживание для обычной развёртки при этой
проверке отключено. После каждой смены предусмотрен прогрев 32 периодов.

На каждой ступени принимаются четыре завершённых блока DMA. Проверяются
версии, границы, частота, возрастание sequence, соответствие first_sample,
ошибки DMA и overflow, которые контролирует драйвер. В первых 4096 байтах
каждого блока рассчитываются min/max отдельно для CH1-A, CH2-A, CH1-B и CH2-B.
Уровень, который во всех проверенных отсчётах ветви равен только 0 или только
255, останавливает запуск с указанием канала, ветви, кода и частоты.
Пройденные диапазоны печатаются в UART-консоль.

Постоянный код 128 допустим для постоянного входного сигнала. Код 0/255
может означать насыщение аналогового входа, его неверное смещение или проблему
цифрового приёма; сообщение не объявляет конкретную причину установленной.
Без известного тестового напряжения эта проверка не подтверждает аналоговую
точность и не обнаруживает все варианты застывших цифровых шин. В AD9288
не задействован внутренний генератор тестовой последовательности.

При первом отказе дальнейший подъём частоты прекращается. При успехе
проверяется номинальная ступень и разрешается обычный запуск GUI.
Физическое измерение клоков, реакция на входное напряжение и точность
интерливинга остаются проверками на плате.
