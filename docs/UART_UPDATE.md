# Обновление Zynq по UART

В Oscill Terminal подключиться к P1, дождаться входа в Linux, открыть
«Прошивка» и выбрать каталог с `BOOT.BIN` и `image.bin`. Нажать
«Перепрошить прибор». Прогресс отображается в терминалке и в режиме
обновления на HDMI. После проверки записи прибор перезагружается.
GUI останавливается до передачи; на экране последовательно отображаются
PREPARING, RECEIVING, WRITE AND VERIFY и COMPLETE. Автоматического создания
резервной копии нет. Оба переданных файла проверяются SHA-256 до записи,
записанные данные читаются обратно и сверяются с образами.

Передаются отдельные образы реальной длины, без хвоста 16-МиБ `qspi.bin`.
Области резервного окружения и настроек сохраняются. Передача не удаляет
байты `00` или `FF` из полезных данных файла. Максимальные размеры:
BOOT — 0x500000, FIT — 0x9e0000; адрес FIT — 0x520000.

При первой установке поверх прошивки с read-only разделами MTD терминалка
останавливает U-Boot, передаёт FIT командой loadb и загружает его из RAM.
На этом этапе прогресс передачи виден на ПК. Параметр `oscill.update=1`
запускает новый Linux сразу в режиме обновления с экраном прогресса,
без запуска захвата со старым FPGA. Он записывает оба образа. Следующие обновления
проходят напрямую в Linux. Скорость UART должна совпадать на обеих сторонах;
для загрузочных этапов текущей сборки терминал переключает порт на 1000000 бод.
Тот же RAM-переход используется, если старый драйвер не завершает остановку
GUI. На старом загрузчике до запуска временного Linux остаётся заставка FSBL;
передача для записи начинается уже в Linux с экраном обновления.

## Реализация и проверки

`TERMINAL/firmware.py` отвечает за последовательность обновления,
`kermit.py` — за совместимый с U-Boot loadb транспорт, `firmware_ui.py` — за
вкладку. Портом продолжает владеть единственный SerialWorker; обновление
занимает соединение до завершения. Длинные пакеты Kermit имеют проверку и
повторы; контроль CRC32 полного RAM-образа обязателен перед bootm.

`firmware_flash.c` проверяет размеры, заголовки, CRC и геометрию MTD до
стирания. Сначала обновляется FIT, затем BOOT. Записываются только занятые
блоки erase по 64 КиБ, каждый читается обратно и сравнивается побайтно.
`firmware_update.c` связывает запись с существующим framebuffer-драйвером
и отдельным экраном общего renderer. Возврат в обычный режим — перезагрузка
после успешной проверки. Проверки файлов и MTD выполняются также на ПК с
подменой аппаратных вызовов; это не заменяет проверку на плате.
