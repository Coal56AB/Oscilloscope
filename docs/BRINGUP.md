# Первый запуск Zynq-7020

## Тест платы

1. Скопировать `ZYNQ7020/output/diagnostic/BOOT.BIN` в корень FAT32-карты, вставить в **TF1**.
2. Выбрать TF1 переключателем SW1: код `11` по схеме платы. Перезапустить питание.
3. Подключить HDMI и USB-UART **P1**, открыть терминал **115200, 8N1**.
4. Дождаться `DDR result: PASS`, затем проверить цвета, рамку и движущуюся линию на экране.

Проверяются 464 МиБ DDR с отключённым кэшем. Полоса снизу: жёлтая до окончания теста, зелёная при PASS, красная при ошибке. UART печатает первые адреса ошибок. В этой прошивке USB-тач проверяется следующим этапом.

## Linux и GUI

В `ZYNQ7020/output/linux/` находятся `BOOT.BIN`, `image.bin` (FIT: ядро, Device Tree, initramfs), полный `qspi.bin` и `fsbl.elf` для SDK Program Flash. Адреса раздельной записи BOOT/FIT — 0 и 0x520000 соответственно. Запись и резервное копирование описаны в [FLASHING.md](FLASHING.md); режим SW1 для QSPI — код `10` по схеме.

Предупреждения и ошибки ядра, сообщения запуска служб выводятся в UART. GUI с демонстрационными сигналами и штатным меню DEBUG запускается без дополнительной паузы (`START_DELAY=0`); U-Boot также не выдерживает паузу автозагрузки (`BOOTDELAY=0`). Периодическая диагностика приложения по умолчанию отключена (`DIAGNOSTICS=0`); для её вывода в UART включить `DIAGNOSTICS=1` в `/etc/default/oscill` перед сборкой rootfs. USB сенсора подключается к **P3**; приложение само ищет сенсор с одним контактом или Type B мультитачем и повторяет поиск после отключения. Pinch требует двух контактов. HDMI подключается отдельно. Поворот, задержка запуска и интерфейсы — в `/etc/default/oscill`.

Для проверки поворота без пересборки: остановить GUI командой `/etc/init.d/S99oscill stop`, затем запустить `scope_preview --fb /dev/fb0 --touch auto --touch-rotate 180 --diagnostics`. Журнал загрузки и диагностика остаются в UART; после конфигурации FPGA до первого кадра GUI экран показывает логотип. Настройки постоянного запуска меняются в `ZYNQ7020/linux/rootfs-overlay/etc/default/oscill` перед сборкой rootfs.

Панель STM32 подключается своим USB–UART мостом к hub вместе с сенсором,
hub — к P3. При `SERIAL_DEVICE=auto` GUI ищет панель автоматически на 115200 бод.
Проверить кнопки, энкодеры, итоговые масштабы обоих каналов, LED RUN и повторное
подключение USB. При включённой диагностике `uart_device` показывает путь порта,
`uart_link` — получение пакетов панели.

Проверка из UART-консоли:

Логин — `root`, пароль не задан.

```sh
lsusb
cat /proc/bus/input/devices
evtest /dev/input/eventN
dmesg -w
```

В `evtest` проверить ABS_X/Y и BTN_TOUCH либо независимые `ABS_MT_TRACKING_ID`, затем в GUI — касания и, для мультитача, pinch. Номер `eventN` берётся из фактически обнаруженного сенсора. В диагностике `touch_connected`, `connections`, `reports`, `events`, `overflows` показывают подключение и поток событий; последние три счётчика относятся к текущему подключению. Сообщение `USB disconnect` в `dmesg` означает потерю USB-устройства, даже если приложение ещё ищет его повторно. Если USB остаётся подключённым, сравнить события `evtest` со счётчиками GUI. Autosuspend USB отключён для этого теста; это не устраняет неисправный кабель или питание. Если устройство не перечисляется, проверяются ULPI reset, VBUS и кабель P3.

Для BMP/CSV вставить карту с exFAT или FAT32 в TF2. Носитель с меткой `OSCILL` подключается автоматически; другой носитель один раз выбрать командой `oscill-card mount /dev/mmcblk1p1` для карты с одним разделом. Выбор запоминается на носителе; при следующей загрузке и повторной вставке он подключается автоматически. Перед извлечением — `oscill-card unmount`. Без смонтированного носителя сохранение выдаёт `NO DATA CARD`; в оперативную память BMP/CSV не записываются. Уведомления отображаются три секунды.

Первый комплект использует DDR 400 МГц, CPU 600 МГц и HDMI 1024×600 при 50 МГц pixel clock (расчётно 60,005 Гц). Семейство DDR задано по схеме; speed bin памяти и установленного FPGA не считаны. Для сборки выбран самый медленный `xc7z020clg400-1`; это не утверждение о маркировке платы. Совместимость видеорежима и работа сенсора устанавливаются этим запуском.

АЦП и физический обмен STM32 с Zynq ещё не проверены. Сборка исходников — [BUILD.md](BUILD.md).

## Служебный OLED

После обновления FPGA/FSBL и Linux по [FLASHING.md](FLASHING.md) проверить раннюю
надпись OSCIL BOOT и переход к GUI / HDMI. K1 должна последовательно переключать
страницы; удержание не должно давать повторов. Захват/обработка отделены от GUI,
питание/аккумулятор имеют свою страницу, доступные температуры — свои подстраницы.

Сверить отображаемые напряжение и температуры с фактической телеметрией панели
и sysfs Linux. Неподключённая панель не должна давать вымышленное напряжение,
а неподдерживаемые показатели аккумулятора должны оставаться N/A. Отсутствие
свежего GUI heartbeat должно показываться как TIMEOUT отдельной службой.
Источники данных и ограничения профиля OLED — [STATUS_DISPLAY.md](STATUS_DISPLAY.md).
