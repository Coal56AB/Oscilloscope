# Первый запуск Zynq-7020

## Тест платы

1. Скопировать `ZYNQ7020/output/diagnostic/BOOT.BIN` в корень FAT32-карты, вставить в **TF1**.
2. Выбрать TF1 переключателем SW1: код `11` по схеме платы. Перезапустить питание.
3. Подключить HDMI и USB-UART **P1**, открыть терминал **115200, 8N1**.
4. Дождаться `DDR result: PASS`, затем проверить цвета, рамку и движущуюся линию на экране.

Проверяются 464 МиБ DDR с отключённым кэшем. Полоса снизу: жёлтая до окончания теста, зелёная при PASS, красная при ошибке. UART печатает первые адреса ошибок. В этой прошивке USB-тач проверяется следующим этапом.

## Linux и GUI

Комплект Linux содержит `BOOT.BIN`, `boot.scr`, `zImage`, `oscill-zynq7020.dtb` и `rootfs.squashfs`. Образ `sdcard.img` объединяет загрузочную FAT32 и корневую SquashFS; его записывают на тестовую карту целиком. Используется тот же слот TF1 и тот же аппаратный проект.

Для постоянной загрузки без карты подготовлены `BOOT.BIN` и `image.bin` (FIT: ядро, Device Tree, initramfs), а также полный `qspi.bin`. Адреса — 0 и 0x520000 соответственно. Запись и резервное копирование описаны в [FLASHING.md](FLASHING.md); режим SW1 для QSPI — код `10` по схеме.

Сообщения ядра и запуска служб выводятся в UART и на HDMI-экран. Через четыре секунды после запуска служб открывается существующий GUI с демонстрационными сигналами и штатным меню DEBUG; диагностика приложения раз в секунду идёт в UART. USB сенсора подключается к **P3**; приложение само ищет сенсор с одним контактом или Type B мультитачем и повторяет поиск после отключения. Pinch требует двух контактов. HDMI подключается отдельно. Поворот, задержка запуска и интерфейсы — в `/etc/default/oscill`.

Для проверки поворота без пересборки: остановить GUI командой `/etc/init.d/S99oscill stop`, затем запустить `scope_preview --fb /dev/fb0 --touch auto --touch-rotate 180 --diagnostics`. Журнал загрузки и диагностика остаются в UART; после конфигурации FPGA до первого кадра GUI экран показывает логотип. Настройки постоянного запуска меняются в `ZYNQ7020/linux/rootfs-overlay/etc/default/oscill` перед сборкой rootfs.

Проверка из UART-консоли:

Логин — `root`, пароль не задан.

```sh
lsusb
cat /proc/bus/input/devices
evtest /dev/input/eventN
dmesg -w
```

В `evtest` проверить ABS_X/Y и BTN_TOUCH либо независимые `ABS_MT_TRACKING_ID`, затем в GUI — касания и, для мультитача, pinch. Номер `eventN` берётся из фактически обнаруженного сенсора. В диагностике `touch_connected`, `connections`, `reports`, `events`, `overflows` показывают подключение и поток событий; последние три счётчика относятся к текущему подключению. Сообщение `USB disconnect` в `dmesg` означает потерю USB-устройства, даже если приложение ещё ищет его повторно. Если USB остаётся подключённым, сравнить события `evtest` со счётчиками GUI. Autosuspend USB отключён для этого теста; это не устраняет неисправный кабель или питание. Если устройство не перечисляется, проверяются ULPI reset, VBUS и кабель P3.

Для BMP/CSV вставить карту с exFAT или FAT32 в TF2 и выполнить `oscill-card mount /dev/mmcblk1p1` для карты с одним разделом. Перед извлечением — `oscill-card unmount`. Без смонтированного носителя сохранение выдаёт `NO DATA CARD`; в оперативную память BMP/CSV не записываются.

Первый комплект использует DDR 400 МГц, CPU 600 МГц и HDMI 1024×600 при 50 МГц pixel clock (расчётно 60,005 Гц). Семейство DDR задано по схеме; speed bin памяти и установленного FPGA не считаны. Для сборки выбран самый медленный `xc7z020clg400-1`; это не утверждение о маркировке платы. Совместимость видеорежима и работа сенсора устанавливаются этим запуском.

АЦП и STM32 к этому тесту ещё не подключены. Сборка исходников — [BUILD.md](BUILD.md).
