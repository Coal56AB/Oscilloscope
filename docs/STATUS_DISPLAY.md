# Задний служебный OLED Zynq

OLED12864 на модуле ZYNQ MINI rev B показывает состояние прибора независимо от
отрисовки основного HDMI-интерфейса. **K1** переключает страницы по кругу; одно
нажатие даёт один переход, удержание не повторяется, дребезг фильтруется 50 мс.
После включения выбрана страница GUI. Автоматического перелистывания нет.

## Страницы

| Страница | Данные |
|---|---|
| GUI / HDMI | Состояние процесса, частота программной отрисовки, среднее время кадра, видеорежим |
| Capture | Источник DEMO / RAW DEMO / FILE / ADC, RUN/STOP; для raw pipeline — обработанные блоки и время обработки |
| Connections | Состояние панели STM32 и USB-сенсора, фактический IPv4 |
| Power / Battery | Напряжение `ANALOG_VBAT` от STM32; процент заряда, ток и состояние зарядки пока `-` |
| Storage | Наличие смонтированного отдельного блочного носителя данных, доступное место и read-only; фактический режим системной ФС |
| System / Versions | Версия приложения, первые 12 hex SHA-256 собранного bitstream, загрузка CPU, MemAvailable, uptime |
| Errors | Активная и последняя ошибка, ошибки/пропуски UART. Последняя ошибка сохраняется до завершения службы/перезагрузки |
| Temperatures | STM32, затем обнаруженные каналы hwmon, IIO и thermal; название и °C, по три датчика на страницу |

Общее правило интерфейса: короткое понятное название и актуальное значение;
если данных нет, произошла ошибка чтения или показание устарело — прочерк `-`.
Возраст, FRESH/STALE, UNAVAILABLE, N/A и служебные пояснения не выводятся на
обычных страницах. Таймауты продолжают действовать внутри. Диагностика UART
находится на Errors; подробные счётчики захвата доступны в `--diagnostics`.

Основной DEMO не выдаёт метрики аппаратного захвата; CSV-просмотр также не
подменяется статистикой raw pipeline. Название ADC зарезервировано для будущего
реального источника: текущий frontend его не выбирает. FPS относится к вызовам
renderer, а не к доказанной частоте HDMI scanout. У платы нет подключённого HPD,
поэтому наличие монитора и качество HDMI-соединения определить невозможно.

Служба читает sysfs заново каждую секунду. Поддержаны `hwmon/temp*_input`
(миллиградусы), `IIO/in_temp*_raw` с предоставленными драйвером scale/offset,
`IIO/in_temp*_input` (готовые миллиградусы) и
`thermal_zone*/temp`. Датчик с ошибкой чтения показывается как `-`;
отсутствующие датчики не заменяются расчётами. Ограничение — 64 канала, при его
достижении последующие каналы не добавляются. Разные sysfs-представления одного
датчика могут отображаться отдельно; драйверные подписи сохраняются.
Включён PS-драйвер XADC; его название на OLED — ZYNQ. Первое место всегда
отведено STM32, включая отсутствие связи или старую прошивку панели: тогда `-`.
Телеметрия температуры STM32 передаётся раз в секунду отдельным пакетом UART,
через snapshot transport и локальный status IPC. Датчики АЦП, аккумулятора и
окружающего воздуха появятся только при наличии измерения и его экспорта.
Отдельных температур PS и PL
из единственного канала температуры кристалла не создаётся.

Напряжение вычисляет существующая прошивка STM32 из ADC9 и делителя R32/R33
100k/100k с заданной опорой. Это не калиброванное измерение процента заряда.
Без типа/числа элементов, характеристики разряда и сигнала зарядного устройства
SOC/ток/зарядка не определяются. Показание старше трёх секунд заменяется прочерком.

## Загрузка, ошибки и зависание GUI

После конфигурации FPGA и снятия PS/PL reset FSBL инициализирует OLED тем же
переносимым драйвером, что и Linux, и выводит этап загрузки. После старта Linux
`S20oscill-status` запускает отдельный процесс `oscill-status`. Он не зависит от
SDL, framebuffer или работоспособности GUI и повторяет поиск UIO при отсутствии
устройства. `S99oscill` сообщает STARTING/ошибку запуска/STOPPED.

GUI отправляет один неблокирующий AF_UNIX datagram в секунду из главного цикла.
Пакет содержит версию, размер, источник и снимок уже существующих метрик; служба
не читает изменяемое состояние приложения напрямую. Нет службы или переполнена
очередь — пакет пропускается, GUI продолжает работать. Локальный сокет доступен
только владельцу (0600); повторный экземпляр службы исключён lock-файлом.

Отсутствие heartbeat READY более трёх секунд даёт GUI TIMEOUT. Для запуска
предусмотрено 15 секунд; намеренный STOPPED не считается зависанием. Начало
нового запуска сбрасывает стартовый таймаут. Новая ошибка автоматически открывает
Errors один раз. K1 позволяет уйти с неё даже при сохраняющейся ошибке. Потери
данных, ошибки источника, предупреждения GUI и отсутствие панели/сенсора после
стартового интервала сохраняются в последней ошибке. Старые показания заменяются
прочерками. Для питания и температуры STM32 учитывается сумма возраста отсчёта
при отправке и времени после получения пакета GUI, без переполнения счётчиков.

Внутренний датчик STM32F103RCT6 доступен на ADC1_IN16, см.
[даташит ST, раздел Temperature sensor](https://www.st.com/resource/en/datasheet/stm32f103ze.pdf).
Прошивка опрашивает ADC1_IN9 (питание), ADC1_IN16 (температура) и ADC1_IN17
(VREFINT) последовательно без ожидания готовности в главном цикле. Значение
температуры оценивается по типовым коэффициентам ST с учётом измеренного
отношения к VREFINT: это температура кристалла, не воздуха или экрана.
Индивидуальная калибровка не выполнялась. Коэффициенты и ограничения описаны
в [STM32.md](STM32.md#температура-кристалла).
У OLED текущий serial-интерфейс используется только для вывода; подтверждённого
канала температурной телеметрии нет. Для основного HDMI-дисплея такой канал также
не подтверждён: DDC не подключён, USB используется сенсором. Наличие датчика
в неизвестном контроллере дисплея не означает доступ к нему из этого проекта.

## Аппаратный путь

Распиновка визуально сверена с [оригинальной схемой](zynq7020/ZYNQ_MINI_REVB%20Schematic.pdf),
листы 4, 5, 9, 12: OLED D0=E18, D1=E19, D/C=F16, RST=F17;
**K1=PS MIO0 (E6)**, K2=PL KEY1 (M20), K3=PL KEY2 (M19).
Кнопки активны низким уровнем, имеют подтяжки PR9 к 3,3 В.
CS OLED посажен на землю. K2/K3 пока не назначены. Прежнее чтение M19
ошибочно называлось K1 и фактически реагировало на K3, что проверил владелец.

AXI GPIO по `0x41200000` обслуживает OLED (канал 1, четыре выхода) и PL-кнопки
K3/K2 (канал 2, два входа с CDC внутри IP), которые служба больше не читает.
Linux UIO открывает только этот регистровый блок по имени `oscill-oled`,
а не произвольную физическую память. Framebuffer и DMA-захват не отображаются.
Доступ защищён flock; единственный владелец OLED GPIO — служба.
Для K1 отдельный Linux-драйвер приложения выбирает gpiochip по label `zynq_gpio`
и запрашивает только линию MIO0 через GPIO character-device API v1 как input,
active low. Номер `/dev/gpiochipN` не фиксирован; PL GPIO не подменяет PS GPIO.
Ошибка/занятая линия приводит к повтору открытия через две секунды, без изменения
других линий. Чтение K1 отделено от транспорта OLED, debounce остаётся в модели.
В ядре включены GPIO_ZYNQ, GPIO_CDEV и GPIO_CDEV_V1; новые выводы FPGA не нужны.
Частота опроса K1 — до 50 Гц. Полный serial update занимает дополнительное
время; shadow framebuffer отправляет только изменённые диапазоны страниц.

Профиль команд **SSD1306 128×64** и шрифт перенесены из `Zynq_study`
(`sdk/lib/oled`, `sdk/lib/common/font5x7`) в переносимый код со стандартными
типами. Проект не зависит от соседней рабочей копии. Схема содержит OLED12864,
но не маркировку контроллера: SSD1306 остаётся явно выбранным совместимым
профилем, а не установленным по схеме фактом.

## Проверка без устройства

```sh
ctest --test-dir /absolute/gui-build --output-on-failure
python3 ZYNQ7020/linux/tests/test_status_service.py /absolute/gui-build
/absolute/gui-build/oscill-status --once --text --page 7 --pbm /tmp/temperatures.pbm
```

`--page` принимает индекс с нуля; страницы температуры начинаются с 7.
`--text` отключает физический OLED, `--pbm` сохраняет его настоящий буфер 128×64.
Интеграционный тест запускает собственные SDL GUI и службу, приостанавливает
только созданный им GUI через SIGSTOP и проверяет TIMEOUT, восстановление и
завершение. Подробности фактических сборок — [TESTING.md](TESTING.md).

Для установки нужен новый bitstream/FSBL **и** Linux-образ. Одного обновления
приложения недостаточно для добавленного AXI GPIO. Автоматической записи QSPI
нет; работоспособность OLED, K1, температурных каналов и напряжения на реальном
устройстве проверяется после штатной прошивки.
