## STM32 и АЦП основной платы

В `PCB/AnalExtend/AnalExtend.SchDoc` указаны `AD9288BSTZ-100`; в `Interfaces.SchDoc` — модуль `STM32F103RCT6` с двумя PBD 2×14. Маркировки прочитаны из записей Altium; это не проверка установленных компонентов или электрической связности PCB.

[AD9288 Rev. C](https://www.analog.com/media/en/technical-documentation/data-sheets/AD9288.pdf) описывает две 8-битные ветви до 100 MSPS у версии -100. Два AD9288 дают четыре 8-битные шины, то есть 32 линии данных. Интерливинг двух ветвей одного канала при сдвиге тактов на половину периода — целевое решение; сам факт применения -100 не подтверждает корректность фаз, аналоговой полосы или gain/offset alignment.

CAM1 оставляет после 32 линий данных только 2 I/O. Нужно сверить все тактовые линии, генератор фаз, служебные сигналы и UART с фактическими соединениями основной платы. Если требуются четыре отдельных выхода тактов из PL и UART на этом же разъёме, 34 контактов недостаточно. Общий внешний генератор/освобождённые выводы меняют расчёт; вариант не выбран без проверки соединений.

UART STM32 нельзя напрямую подключить к USB D+/D− P1. Возможные реальные пути: отдельный UART через EMIO и подтверждённые PL pins; подключение к 3,3-вольтовой стороне U9/U10 с исключением конфликта выхода CH340; внешний USB-UART на PS USB Host через hub. Последний делит USB Host с сенсором. Ни один путь в текущем ПО не объявлен физически подключённым.

## Перед первым запуском платы

Handoff и FSBL получены из `ZYNQ7020/build.ps1`: DDR ×16, 512 МиБ, заданные 400 МГц; CPU 600 МГц. Режим HDMI — 1024×600, pixel clock 50 МГц, totals 1344×620. Первый тест запускается с TF1 по [BRINGUP.md](../BRINGUP.md).

На плате проверить DDR training и тест памяти; ULPI reset/clock/CPEN и VBUS; USB enumeration и два независимых tracking ID сенсора; видеорежим дисплея. Для последующих аппаратных этапов нужны маркировки U8/U1/U15, подключение STM32, распиновка АЦП и фазы. Резервная копия QSPI нужна перед её изменением. Эти проверки не заменяются успешной компиляцией.
