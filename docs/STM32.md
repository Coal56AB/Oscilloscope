# Контроллер панели STM32F103RCT6

## Проект

`STM32/oscill_controls.ioc` — конфигурация CubeMX 6.12.1, STM32CubeF1 1.8.7.
`STM32/MDK-ARM/oscill_controls.uvprojx` — проект Keil MDK-ARM с Arm Compiler 6.
Выбран STM32F103RCT6: Flash 256 КиБ, SRAM 48 КиБ. Startup называется
`startup_stm32f103xe.s`: ST использует этот файл для семейства F103xC/xD/xE.

```text
STM32/
├── oscill_controls.ioc
├── Core/
│   ├── Inc/        заголовки генерируемой периферии
│   ├── Src/        генерируемая периферия и main.c
│   └── Oscill/     прикладные модули, пары .c/.h
├── Drivers/        локальные HAL/CMSIS с лицензиями ST/Arm
├── AllLibs/        субмодули PeriphGeneral и MyLibs
├── MDK-ARM/        проект Keil и startup
└── tests/          переносимые проверки панели и UART
```

Прикладной каталог `Core/Oscill` устроен по образцу `Core/UIPS`: пары `.c/.h`
расположены рядом, `oscill_main` связывает модули через их API. Периферию
настраивает CubeMX; `board_controls.c` связывает GPIO с библиотеками,
`controls.c` хранит готовые события, `panel_state.c` владеет масштабами и выбирает
реле, `board_outputs.c` применяет GPIO и читает ADC питания, `controls_uart.c`
обслуживает двусторонний UART, `oscill_main.c` связывает модули.
Общий codec включён из `ZYNQ7020/gui/src/control_protocol.c`, без копирования.

`AllLibs/PeriphGeneral` подключён из [STM32_General](https://git.rd12.ru/Templates/STM32_General.git),
`AllLibs/MyLibs` — из [ExtendedLibs](https://git.rd12.ru/Templates/ExtendedLibs.git).
Версии закреплены gitlink; подготовка рабочей копии — `git submodule update --init --recursive`.
Конфигурация HAL и времени находится в `Core/Oscill/mylibs_config.h`.
`GPIO_Read_Switch` используется с фильтром `Sw_FilterDelay`. `Encoder_Init` принимает порты и пины A/B и число переходов
на детент. `Encoder_Update(&encoder)` сама читает GPIO, обрабатывает фазы
и возвращает −1, 0 или +1. Библиотека не зависит от номеров каналов, очереди
или UART; каждая кнопка и энкодер имеют собственное состояние.

## Настройки CubeMX

- HSI 8 МГц → HSI/2 × PLL16 → SYSCLK/HCLK 64 МГц; APB1 32 МГц, APB2 64 МГц.
- SysTick 1 мс; входы панели — GPIO input с pull-up.
- SYS Debug — Serial Wire: PA13/PA14 доступны для SWD; PB3/PB4/PA15 освобождены от JTAG.
- USART1 PA9/PA10, 115200 8N1, без flow control; IRQ priority 2. TX/RX через HAL IT.
- PA0…PA5 — выходы реле; PB1 — ADC1_IN9, одиночный программный запуск,
  sampling time 239,5 такта, ADC clock HCLK/6 ≈ 10,67 МГц.
- `Generate peripheral initialization as a pair of .c/.h files`, `Keep User Code` включены.
- HAL/CMSIS копируются в проект; сборка не обращается к соседним рабочим копиям.

Внутренний HSI выбран для первого запуска: частота кварца установленного модуля
не установлена. 64 МГц — настройка проекта, а не измеренная частота.

## Входы панели

Источник — символ модуля и подписи цепей `PCB/AnalExtend/Interfaces.SchDoc`
в PCB commit `5c4f6dd616d461db2b3ec94a01ae66af5781a7e2`.
Номера GPIO относятся к STM32, не к порядку контактов PBD.

| Назначение GUI | Цепи на схеме | A | B | Кнопка |
|---|---|---|---|---|
| CH1 | CH0 | PB8 | PB7 | PB9 |
| CH2 | CH1 | PB5 | PB4 | PB6 |
| TIME | TIME | PD2 | PC12 | PB3 |
| TRIGGER | TRG | PC10 | PA15 | PC11 |
| FUNCTION | FUNC | PC8 | PC9 | PA8 |

| Кнопка GUI | Цепь | GPIO |
|---|---|---|
| CH1 | EN_CH0 | PB11 |
| CH2 | EN_CH1 | PB10 |
| CURSOR | CURSOR | PB13 |
| MODE | TRG_MODE | PB12 |
| MENU | MENU | PB15 |
| RUN | RUN | PB14 |

Контакты замыкаются на GND; драйвер нормализует LOW в «нажато». Настройки первого
запуска: debounce 5 мс, четыре перехода фаз на детент, опрос при смене SysTick.
Направление вращения, переходы на детент и дребезг проверить на реальных энкодерах.
LED_RUN подключён к PC7, активный уровень — HIGH. При старте он выключен;
`board_controls_set_run_led` управляет им через библиотеку GPIO. В обычной сборке
индикатор следует последней принятой команде RUN от GUI.

## Масштабы и реле

STM32 хранит масштабы CH1/CH2. В обычном режиме энкодеров их повороты меняют
местные значения; в UART уходят абсолютные мВ/дел, без повторной отправки дельты
масштаба. Начальные значения — 500 мВ/дел и 1 В/дел. Запросы масштаба от сенсорного
экрана и меню применяет STM32; GUI обновляет значение по ответу панели. Положение
каналов, развёртка TIME и остальные функции остаются в GUI. Для режима позиции
GUI сообщает назначение энкодера; тогда STM32 передаёт его обычные шаги.
Коэффициент щупа ×10 учитывает GUI, он не меняет входной делитель платы.

| Цепь | GPIO | Бит внутренней маски |
|---|---|---:|
| RELAY_A1 / A2 / A3 (CH1) | PA3 / PA4 / PA5 | 0 / 1 / 2 |
| RELAY_B1 / B2 / B3 (CH2) | PA2 / PA1 / PA0 | 3 / 4 / 5 |

Источник соединений — `Interfaces.SchDoc`, а резисторов и драйверов —
`DiffMeasure.SchDoc` текущей PCB. HIGH включает NPN и катушку HFD4/3-S,
размыкая нормально замкнутый шунт соответствующего резистора.

| Масштаб входа, мВ/дел | RELAY_1 | RELAY_2 | RELAY_3 | Расчётный коэффициент входа |
|---|---:|---:|---:|---:|
| 100, 200 | 1 | 1 | 1 | 0,49037 |
| 500, 1000, 2000 | 0 | 1 | 1 | 0,04962 |
| 5000 | 0 | 0 | 1 | 0,00518 |

Расчёт: каждая входная цепочка — 5 × 200 кОм = 1 МОм; нижнее плечо —
510 Ом плюс включённые 910 кОм, 47 кОм и 4,7 кОм. Коэффициент равен
`Rниж / (1 МОм + Rниж)`, дифференциальный gain AD8138 по RГ/RОС — 1.
Выбирается наиболее чувствительная из этих ступеней, при которой восемь делений
укладываются в номинальные 1,024 Vpp [AD9288](https://www.analog.com/media/en/technical-documentation/data-sheets/ad9288.pdf).
Это расчёт по номиналам, не калибровка или измерение тракта.

Шесть GPIO обновляются одним BSRR. При изменении ступени STM32 выдерживает
`STM32_RELAY_SETTLE_MS` (10 мс), затем публикует итоговый масштаб. Пауза — настройка
первого запуска; фактическое установление контактов и тракта проверяется на плате.
Поворот внутри одной аппаратной ступени не вызывает повторного переключения реле.
Снимок масштабов повторяется раз в секунду для восстановления экрана после потерь.

## Измерение питания

`AnalExtend.SchDoc`: R32/R33 по 100 кОм делят напряжение перед R32 пополам;
`ANALOG_VBAT` подключён к PB1. ADC калибруется при запуске и опрашивается раз в
секунду, без ожидания завершения в цикле панели. При сбое замера новое значение
не публикуется. UART передаёт мВ до делителя:
`round(ADC × STM32_ADC_REFERENCE_MV × 2 / 4095)`.
Опора по умолчанию — номинальные 3300 мВ; для калибровки в `oscill_config.h`
задаётся измеренное VREF+. Процент заряда и признак зарядки из напряжения не
выводятся. В GUI напряжение доступно в `SerialControlMetrics` и `--diagnostics`
вместе с возрастом последнего замера.

## Температура кристалла

Раз в секунду `board_outputs_sample()` последовательно опрашивает ADC1_IN9,
ADC1_IN16 (внутренний датчик) и ADC1_IN17 (VREFINT). Между вызовами ADC работает
самостоятельно; Poll имеет timeout 0, каждый канал имеет предельное время 10 мс.
Сбой одного канала не отменяет остальные. Ранг 1 переключается прикладным
драйвером; стартовая конфигурация ADC9 в CubeMX сохраняется. HAL включает TSVREFE
и выдерживает старт датчика 10 мкс; выборка 239,5 такта при ADC 10,67 МГц —
расчётные 22,45 мкс, больше минимума 17,1 мкс из DS5792.

`panel_state_temperature_mc()` переводит raw16/raw17 в м°C:
`Vsense = ADC16 / ADC17 × VREFINT`,
`T = 25 + (V25 - Vsense) / slope`.
По умолчанию `STM32_VREFINT_MV=1200`, `STM32_TEMPERATURE_V25_MV=1430`,
`STM32_TEMPERATURE_SLOPE_UV_PER_C=4300` — типовые параметры
[ST DS5792](https://www.st.com/resource/en/datasheet/stm32f103ze.pdf),
а не индивидуальная калибровка установленного чипа. Это оценка температуры
кристалла; точность на плате не измерена. Для индивидуальной калибровки
коэффициенты переопределяются в `oscill_config.h`.

Отвергаются raw на границах 0/4095, расчётное VDDA вне 2,4–3,6 В и температура
вне −40…125 °C. Эти проверки выявляют некорректное чтение, но не подтверждают
точность датчика. Успех передаётся TEMPERATURE=10, ошибка — INT32_MIN.
OLED всегда содержит строку STM32: актуальное число либо `-` без служебных
подписей. Поддержка требует новых прошивок STM32 и Zynq. Температура OLED или
основного экрана по существующим соединениям не доступна.

## Автономная отладка без Zynq

В `Core/Oscill/oscill_config.h` установить `STM32_STANDALONE_DEBUG` в `1`
либо добавить `STM32_STANDALONE_DEBUG=1` в Define компилятора и выполнить Rebuild.
По умолчанию значение — `0`.

При `1` без связи с GUI энкодеры CH1/CH2 выбирают масштаб и переключают реле,
RUN переключает местный LED по нажатию. При получении команд GUI работают штатные
RUN и режим позиции энкодеров. После двух секунд без команд снова действует
автономная отладка; GUI обновляет команды каждые 500 мс. Перепрошивка при подключении
Zynq не требуется. Запуск и опрос не ожидают связи; масштабы, события и питание
продолжают отправляться в UART.

## UART и запуск

Прошивка использует USART1: PA9 — TX, PA10 — RX, 115200, 8N1.
Владелец подтвердил USB–UART мост на своей плате STM32. Его USB подключается
к hub вместе с сенсором, hub — к PS USB Host Zynq (P3). Маркировка моста и его
соединение с PA9/PA10 требуют сверки на конкретном модуле; по фотографии они
не определяются. Назначения USART1 в прошивке приведены выше.
Формат — [CONTROL_PROTOCOL.md](CONTROL_PROTOCOL.md).

GUI по умолчанию использует `SERIAL_DEVICE=auto` и `SERIAL_BAUD=115200`
из `/etc/default/oscill`: ищет панель среди `/dev/ttyUSB*` и `/dev/ttyACM*`,
восстанавливает связь после отключения. Можно указать конкретный device.
USB–UART P1 на Zynq обслуживает отдельную загрузочную консоль.

## Генерация и сборка

Открыть `.ioc`, оставить `MDK-ARM V5.32` и выполнить Generate Code. Затем открыть
`.uvprojx` в Keil и выполнить Rebuild. Результаты Keil направлены в `STM32/output/`
в корне репозитория: `oscill_controls.axf`, `oscill_controls.hex` и map/listing.

Прикладные файлы находятся в группах `Oscill` и `Shared/Control protocol`,
GPIO и энкодеры — в `Libraries/PeriphGeneral`.
Сгенерированный `main.c` подключает `oscill_main.h` в `USER CODE Includes`,
вызывает `Oscill_Init()` в `USER CODE 2`, `Oscill_Process()` в `USER CODE 3`.
Изменения приложения не требуют правки генерируемого кода вне этих секций.
Callbacks UART находятся в отдельном `oscill_main.c`.

После генерации выполнить `python STM32/tests/check_project.py`, затем Rebuild.
Проверка обнаруживает потерю модулей, include-путей, точек подключения, настроек
MCU/SWD/UART и выходного каталога. Она не заменяет сборку или проверку платы.
Реальная повторная генерация проверена отдельно; результаты — [TESTING.md](TESTING.md).

## Отправка и восстановление

Главный цикл — единственный владелец очереди событий. HAL UART IRQ публикует
флаги; TX complete подтверждает событие. Пока HAL читает пакет, буфер не меняется.
При ошибке или отсутствии завершения 50 мс передача отменяется и повторяется
через 10 мс с тем же sequence. Потерянный IRQ не останавливает опрос панели.
Повтор целого пакета отсеивает общий парсер GUI; повреждённый префикс ресинхронизируется.

`controls_uart_metrics()` предоставляет пакеты, ошибки запуска/передачи и таймауты.
`Stm32Controls` хранит переполнения очереди и недопустимые переходы фаз.
Длительные нажатия вычисляет GUI по DOWN/UP, отдельной команды long press нет.
RX callback переносит байты в ограниченное кольцо; CRC, sequence и команды
обрабатывает главный цикл. Переполнение или ошибка приёма сбрасывают незавершённый
пакет. После двух секунд без принятых пакетов разрешается новая эпоха отправителя.

Порядок записи и проверки на STM32 — [FLASHING.md](FLASHING.md#stm32).
Данные MCU — [ST STM32F103RC](https://www.st.com/en/microcontrollers-microprocessors/stm32f103rc.html),
генерация — [STM32CubeMX CLI](https://dev.st.com/stm32cube-docs/stm32cubemx/6.18.0/en/docs/markup/CubeMX_CLI.html).
