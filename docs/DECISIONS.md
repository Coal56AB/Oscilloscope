# Решения и открытые задачи

|---|---|
| Каталоги устройств `PCB`, `STM32`, `ZYNQ7020`; остальные строчными | Уточнение владельца; имена файлов сохранены |
| Один проект Zynq: GUI + PL + Linux | Это одно устройство с общими интерфейсами и релизом |
| Результаты сборки внутри соответствующего устройства | `ZYNQ7020/output` для FPGA/Linux, `ZYNQ7020/gui/output` для симулятора, `STM32/output` для контроллера; общий каталог результатов в корне не используется |
| Логотип в `ZYNQ7020/gui/logo` | Уточнение владельца: понятное имя и меньше каталогов; один модуль используется GUI и FSBL без копий исходников |
| Полная Linux-сборка одной командой `ZYNQ7020/linux/build.ps1` | После отдельной подготовки окружения скрипт последовательно собирает аппаратную часть, FSBL, Linux/GUI, SD/QSPI и архив; настройки компьютера явно хранятся в `ZYNQ7020/output/build-environment.json` |
| GUI обычный каталог, PCB субмодуль | GUI меняется вместе с устройством; Altium имеет отдельную историю |
| Сохранить C renderer, WinAPI и SDL2 | Существующий интерфейс и функции сохраняются |
| Buildroot br2-external | Небольшой воспроизводимый userspace без большого vendor workflow |
| Linux и FPGA на основе проверяемого стенда study, исходники внутри Oscill | Одинаковые версии Buildroot/kernel/U-Boot, без зависимости от соседней рабочей копии; PetaLinux для текущего запуска не требуется |
| Vivado `ZYNQ7020/oscill.xpr`, SDK `ZYNQ7020/oscill.sdk` | Расположение как в study; Tcl и HDL хранятся отдельно, generated-файлы игнорируются Git |
| VDMA AXIS 100 МГц → отдельный CDC → видео 50 МГц | VDMA stream clock/reset согласованы; переход частоты выполняет AXI clock converter |
| QSPI: BOOT по 0, FIT `image.bin` по 0x520000 | Два файла для SDK Program Flash; initramfs включает штатный GUI, 1 МиБ настроек сохранён |
| Заставка сразу после конфигурации PL, до чтения U-Boot; журнал в UART | Общая маска FSBL/Windows; заполнение кадра с D-cache и сбросом в DDR, повторный старт видео не переинициализирует тракт; framebuffer console отключена |
| Скругление готового содержимого общей маской с покрытием пикселей | Размеры, координаты и примитивы интерфейса сохраняются; рамка восстанавливается по дуге, радиус 5 px для верхних/нижних карточек и 10 px для окон и их элементов |
| Окна настроек каждый раз в центре и поверх остальных панелей | Перетаскивание не сохраняется после закрытия; FFT и нижние карточки не перекрывают настройки |
| Курсоры напряжения CH1 и CH2 в общей таблице; Measurements учитывает пересечение по ширине | Не нужен выбор канала; свободное место справа от курсоров доступно для пристыковки |
| Экспорт Linux только на блочный носитель в штатном запуске | Каталог в RAM отвергается; directory fd удерживает выбранную файловую систему, успешное сохранение подтверждается после syncfs |
| Курсоры A → B → FFT при включённом спектре | TIME выбирает частоту, VERTICAL — уровень в dB; курсор FFT появляется вместе с курсорами, A/B/FFT показывается отдельно от режима, FINE уменьшает шаг энкодера |
| FFT с логарифмической осью частот от DF до Fs/2 и вертикальной шкалой −80…0 dB | Общая группировка частот с максимумом сохраняет пики; шкала, подписи и частотный курсор используют один закон, DC исключён |
| Диапазон min/max на каждый экранный столбец | Сохраняет короткие импульсы при сжатии по времени; демо использует экстремумы формы, raw — все отсчёты интервала, рендерер общий |
| Single touch и Type B, reconnect и SYN_DROPPED; USB autosuspend отключён | Устранение ограничений чтения сенсора и диагностика нестабильного USB, без утверждения об устранении аппаратной причины |
| Framebuffer + SDL dummy для первого запуска; optional DRM | Нет подтверждённого GPU; SDL KMSDRM требует GBM/EGL/OpenGL(ES) |
| Raw uint8 до обработки | 400 МБ/с без расширения каждого отсчёта в DDR |
| Interleaving в PL | Нет лишней перестановки полного потока ARM и дополнительного DDR прохода |
| AXI DMA SG, HP0 кандидат для захвата | DMAEngine стандартный путь; выбор HP/частот подтвердить измерением |
| HP2 кандидат для scanout | Возможность отделить видео от capture на уровне HP, DDR остаётся общей |
| PL min/max параллельно raw | ARM full-stream processing конкурирует с видео и несколькими DDR проходами |
| Explicit DMA ownership/cache sync | HP не делает ARM caches автоматически coherent |
| microSD для отдельных записей | SDIO ×4 даже теоретически существенно медленнее 400 МБ/с |
| Подтверждённый владельцем XC7Z020 | XC7Z010 в символах схемы не переопределяет фактическую плату |
| STM32F103RCT6, CubeMX → Keil Arm Compiler 6 | Уточнение владельца; локальные HAL/CMSIS, приложение в отдельных модулях и USER CODE |
| STM32 HSI/PLL 64 МГц, SWD без JTAG | Кварц модуля не установлен; PB3/PB4/PA15 используются панелью |
| USART1 PA9/PA10 для теста проводами | Выводы свободны по схеме; физическое соединение с Zynq пока не задано |

## Реализованная часть

GUI перенесён с локальным резервом истории. Работают переносимые raw источники/кольцо/processor/бинарный codec, threaded demo pipeline, UART codec/queue/reconnect и переносимая STM32 обработка кнопок/энкодеров. SDL frontend подключает raw и serial, framebuffer/DRM и evdev с поиском мультитач-устройства. RTL packer имеет выполненную simulation. Собраны PS/DDR/VDMA/VTC/TMDS проект, FSBL и диагностический `BOOT.BIN` для TF1. Полный Buildroot комплект с U-Boot, Linux, rootfs и GUI собран в SD/QSPI образы; оба варианта загрузки и отрисовка GUI проверены в ARM эмуляторе.

## Следующий порядок работ

1. Проверить полный part/speed suffix и реальный PS DDR handoff. Подтвердить питание USB Host/VBUS, модель дисплея и допустимые video timings; схему UART STM32 и свободные PL pins. Установленные GPIO/clock нельзя угадывать.
2. Запустить собранный тест DDR/HDMI с TF1; затем Linux с GUI и touch на том же аппаратном проекте. Проверить совместимость фиксированного режима 1024×600 при pixel clock 50 МГц. Для page flip реализовать DRM driver для фактического VDMA/VTC; первый запуск использует framebuffer, настроенный FSBL.
3. Подключить ADC I/O/CDC/phase ordering, FIFO overflow/drop counters, timestamps и PL trigger/pretrigger. Packer допускает backpressure, реальный АЦП остановить им нельзя: overflow должен быть обработан явно.
4. Реализовать DMAEngine SG kernel driver по согласованному `capture_uapi.h`; проверить mmap/cache/vладение и подключить lease source к pipeline. Пока `capture_zynq.c` не используется как source общего pipeline.
5. Довести raw GUI: фактический trigger/pretrigger, полный обзор записи/курсорные значения, persistence/smoothing и связь настроек acquisition. Сейчас эти функции исходного демо остаются самостоятельными; raw экспериментальный режим не является их аппаратной реализацией. При ограничении view глубиной записи нужно согласовать фактическую подпись развёртки и CSV metadata.
6. Добавить bounded storage worker, raw export/browser и безопасную обработку извлечения/заполнения карты. Существующие BMP/CSV операции пока синхронны. Большие записи не должны блокировать GUI или переиспользовать DMA-owned буферы.
7. Проверить сгенерированную прошивку STM32 на модуле: GPIO, направление и детенты энкодеров, debounce, SWD и UART. BSP и неблокирующий транспорт реализованы; для связи с GUI выбрать и проверить физический канал к Zynq.
8. Проверить на плате загрузку/восстановление QSPI и выполнить аппаратные нагрузочные проверки. Готовый образ имеет один системный слот; A/B обновление не реализовано. Требуемые 400 МБ/с с HDMI и запасом пока не измерены.
9. При следующей Linux-сборке сократить время до первого кадра GUI и готовности сенсора. Сначала снять временные отметки FSBL → U-Boot → ядро → init → GUI по UART. Отдельно проверить явные паузы `BOOTDELAY=2` и `START_DELAY=4`, чтение полного раздела FIT вместо фактической длины образа и объём UART-диагностики. Сравнить время до и после изменений на плате; текущее время старта ещё не измерено.
