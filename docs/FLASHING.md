# Прошивка и восстановление

Загрузочный комплект для TF1: FSBL, PL HDMI и тест DDR в `ZYNQ7020/output/diagnostic/BOOT.BIN`. Запуск — [BRINGUP.md](BRINGUP.md). Linux использует тот же аппаратный проект и отдельный комплект с U-Boot.

## Zynq-7020

Обновление через подключённый к P1 USB–UART из Oscill Terminal —
[инструкция и устройство обновления](UART_UPDATE.md).

1. Использовать handoff от `ZYNQ7020/build.ps1`: XC7Z020 CLG400, DDR 512 МиБ ×16 при заданных 400 МГц, CPU 600 МГц. Для timing выбран speed grade -1; полный суффикс установленного FPGA и speed bin DDR пока не прочитаны. Фактическую работу проверяет тест платы. QSPI W25Q128 по схеме — 16 МиБ.
2. Сначала пройти диагностический тест DDR/HDMI, затем загрузить Linux-комплект через TF1. U-Boot можно остановить клавишей во время обратного отсчёта в UART-консоли.
3. Проверить размер и контрольные суммы подготовленных образов. Автоматическое резервное копирование отключено по указанию владельца.

4. `assemble-qspi.py` формирует `qspi.bin` из `BOOT.BIN` и `image.bin`. Образ занимает первые 15 МиБ QSPI; последний 1 МиБ настроек в файл не входит. Адреса фиксированы:

| Файл / область | Адрес QSPI | Доступно |
|---|---:|---:|
| `BOOT.BIN` | `0x00000000` | `0x500000` байт |
| Резерв | `0x00500000` | `0x20000` байт |
| `image.bin` (FIT) | `0x00520000` | `0x9e0000` байт |
| Настройки | `0x00f00000` | 1 МиБ |

В SDK Program Flash можно выбрать отдельно `BOOT.BIN` с offset `0x0` и `image.bin` с offset `0x520000`. Дополнительный `.ub` не нужен. Составной `qspi.bin` записывается с offset `0x0` и заканчивается перед областью настроек. Для сохранения настроек стирание должно охватывать только записываемую область, без полного стирания микросхемы. В этом комплекте один системный слот; автоматическое A/B обновление не реализовано.
5. Для записи через JTAG перевести плату в JTAG mode, подключить JTAG и запустить `hw_server`. Команда SDK 2019.1 из корня проекта:

```powershell
C:/Xilinx/SDK/2019.1/bin/program_flash.bat -f ZYNQ7020/output/linux/qspi.bin -offset 0 `
  -flash_type qspi-x4-single -fsbl ZYNQ7020/output/linux/fsbl.elf -verify -url tcp:localhost:3121
```

В окне SDK Program Flash выбрать `Image File` — `ZYNQ7020/output/linux/qspi.bin`,
`FSBL File` — `ZYNQ7020/output/linux/fsbl.elf`, offset `0`, тип `qspi-x4-single`.
Имена параметров проверены по `program_flash -help`. Файл содержит только системную область QSPI.

6. После успешной верификации выбрать QSPI кодом SW1 `10` по схеме, убрать карту из TF1 и перезапустить питание. Проверить загрузку, HDMI, USB Host/multitouch и UART по [BRINGUP.md](BRINGUP.md). Для восстановления используется тот же JTAG способ с собранным `qspi.bin`.

## STM32

Проект STM32F103RCT6 — `STM32/oscill_controls.ioc` и `STM32/MDK-ARM/oscill_controls.uvprojx`. Настройки, распиновка и регенерация — [STM32.md](STM32.md). После успешного Rebuild в Keil HEX создаётся в `STM32/output/oscill_controls.hex`; фактические сборки — [TESTING.md](TESTING.md). Начальная настройка использует HSI/PLL 64 МГц, не зависит от неизвестного кварца модуля.

Подключить ST-Link: SWDIO → PA13, SWCLK → PA14, GND → GND. В Keil выбран ST-Link/SWD и STM32F103RC; записать прошивку командой Download. В настройках Flash Download включён Reset and Run, а пакетная Debug Description отключена: сброс и запуск после проверки выполняет драйвер ST-Link. После `Verify OK.Application running ...` проверить ответ панели на изменение диапазона — один текст журнала не подтверждает запуск приложения.

Не менять read protection/option bytes без необходимости. Проверить DOWN/UP, быстрые вращения, одновременно нажатые кнопки, удержания и UART. Первый тест связи: PA9 → RX USB–UART 3,3 В и GND, 115200 8N1; раз в секунду отправляется heartbeat. Состояние GPIO и алгоритмов на физической плате ещё не проверено.

Для автономной отладки собрать с `STM32_STANDALONE_DEBUG=1`: без связи с GUI энкодеры CH1/CH2 меняют масштабы и реле, RUN переключает местный LED. При связи с GUI работают штатные команды в обеих конфигурациях. Проверить каждую аппаратную ступень и напряжение питания сравнением с мультиметром; при двустороннем обмене проверить итоговый масштаб и следование LED состоянию RUN/STOP.

## Артефакты релиза

В release manifest фиксировать SHA главного проекта и PCB, версии toolchain/Buildroot/kernel/U-Boot, handoff, chip part, register/sample/UART/driver ABI и bitstream identity; для каждого бинарника — размер и SHA-256. Бинарники и большие build trees не добавляются в исходный Git. Изменение одного компонента не должно обходить проверку ABI другого.
