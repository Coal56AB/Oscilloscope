# Прошивка и восстановление

Первый загрузочный комплект для TF1 собран: FSBL, PL HDMI и тест DDR в `output/diagnostic/BOOT.BIN`. Запуск — [BRINGUP.md](BRINGUP.md). Linux использует тот же аппаратный проект и отдельный комплект с U-Boot. Запись на устройство в этом сеансе не выполнялась.

## Zynq-7020

1. Использовать handoff от `ZYNQ7020/build.ps1`: XC7Z020 CLG400, DDR 512 МиБ ×16 при заданных 400 МГц, CPU 600 МГц. Для timing выбран speed grade -1; полный суффикс установленного FPGA и speed bin DDR пока не прочитаны. Фактическую работу проверяет тест платы. QSPI W25Q128 по схеме — 16 МиБ.
2. Сначала пройти диагностический тест DDR/HDMI, затем загрузить Linux-комплект через TF1. U-Boot можно остановить клавишей во время обратного отсчёта в UART-консоли.
3. Считать всю QSPI дважды и сравнить чтения. Для поставляемого U-Boot диапазоны 128…160 МиБ свободны: kernel загружается по 48 МиБ, DTB по 24 МиБ, framebuffer начинается по 496 МиБ. На изменённом образе сначала перепроверить карту памяти.

```text
sf probe 0 25000000 0
sf read 0x08000000 0 0x01000000
sf read 0x09000000 0 0x01000000
cmp.b 0x08000000 0x09000000 0x01000000
fatwrite mmc 0:1 0x08000000 qspi-backup.bin 0x01000000
```

Каждая команда должна завершиться успешно. Сохранить `qspi-backup.bin` с карты на ПК и проверить размер 16 МиБ и SHA-256. Сохранить исходное положение SW1; оставить доступ к JTAG и UART. Если исходная QSPI не читается или сравнение не проходит, запись не выполнять.

4. `assemble-qspi.py` формирует `qspi.bin`, загрузочный скрипт, MTD Device Tree и `qspi-layout.json` из фактических файлов релиза. Весь образ — 16 МиБ; разделы выровнены по 64 КиБ, есть 1 МиБ настроек и две свободные области по 64 КиБ. Скрипт загрузки находится в последнем секторе, его адрес также задан в U-Boot DTB. В этом комплекте один системный слот; автоматическое A/B обновление не реализовано.
5. После backup и по отдельной команде владельца перевести плату в JTAG mode, подключить JTAG и запустить `hw_server`. Команда SDK 2019.1 из корня проекта:

```powershell
C:/Xilinx/SDK/2019.1/bin/program_flash.bat -f output/linux/qspi.bin -offset 0 `
  -flash_type qspi-x4-single -fsbl output/linux/fsbl.elf -verify -url tcp:localhost:3121
```

Имена параметров проверены по `program_flash -help`; запись на плату не выполнялась. Команда заменяет всю QSPI, включая область настроек. Для готового ZIP пути задаются к распакованным `qspi.bin` и `fsbl.elf`.

6. После успешной верификации выбрать QSPI кодом SW1 `10` по схеме, убрать карту из TF1 и перезапустить питание. Проверить загрузку, HDMI, USB Host/multitouch и UART по [BRINGUP.md](BRINGUP.md). Для восстановления используется тот же JTAG способ с сохранённым `qspi-backup.bin`.

## STM32

Подтвердить модель/питание/clock и цепи encoder/button/UART/SWD по Altium и установленному модулю. После этого создать один BSP для фактической платы, связать его с переносимыми `controls.c` и общим UART codec, определить debouncing/poll cadence по измерениям реальных органов управления. Не создавать параллельную прошивку с иной распиновкой.

Сборка требует конкретного startup/linker/HAL или минимальных register drivers; их пока нет. Существующие host-тесты проверяют алгоритм, а не образ STM32. Перед первой записью сохранить читаемую исходную прошивку и настройки option bytes; не менять read protection/option bytes без необходимости. Прошивать через подтверждённый SWD доступ с фактической моделью target. Проверить DOWN/UP, быстрые вращения, одновременно нажатые кнопки, удержания и переподключение UART.

## Артефакты релиза

В release manifest фиксировать SHA главного проекта и PCB, версии toolchain/Buildroot/kernel/U-Boot, handoff, chip part, register/sample/UART/driver ABI и bitstream identity; для каждого бинарника — размер и SHA-256. Бинарники и большие build trees не добавляются в исходный Git. Изменение одного компонента не должно обходить проверку ABI другого.
